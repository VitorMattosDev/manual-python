27  Ordenação, chaves de ordenação e comparação de objetos

O relatório lista as portas da placa em ordem. O código é uma linha, e a saída é esta:

portas = ["porta-1", "porta-10", "porta-11", "porta-2", "porta-3"]
print(sorted(portas))
['porta-1', 'porta-10', 'porta-11', 'porta-2', 'porta-3']

A porta 10 aparece antes da 2. Ninguém abriu um chamado por causa disso, mas todo relatório impresso nos últimos meses saiu com as portas embaralhadas, e o técnico que procura a porta 9 numa placa de 16 desiste antes.

O sorted não está errado. Ele comparou strings, e string se compara caractere a caractere, como o Capítulo 12 mostrou:

print(sorted(["1", "10", "2"]))
print("1" < "10" < "2")
['1', '10', '2']
True

"1" < "2" porque o caractere 1 vem antes do 2 na tabela; "1" < "10" porque a string mais curta que é prefixo da outra vem primeiro. Nada disso tem a ver com o número que o texto representa.

A correção não é mudar a ordenação: é dizer por qual valor ordenar.

def numero(nome):
    return int(nome.split("-")[1])


print(sorted(portas, key=numero))
['porta-1', 'porta-2', 'porta-3', 'porta-10', 'porta-11']

Este capítulo é sobre esse key: o que ele faz, por que ele é a única forma de ordenar em Python 3, e o que acontece quando os objetos que você quer ordenar não sabem se comparar.

27.1 sorted e .sort()

niveis = [-19.5, -31.2, -8.0]
copia = sorted(niveis)
print("sorted devolve:", copia, "| original:", niveis)
devolvido = niveis.sort()
print("sort devolve:  ", devolvido, "| original:", niveis)
print("sorted de tupla vira lista:", sorted((3, 1, 2)), type(sorted((3, 1, 2))))
print("sorted de dict:", sorted({"b": 1, "a": 2}))
print("reverse:", sorted([1, 3, 2], reverse=True))
sorted devolve: [-31.2, -19.5, -8.0] | original: [-19.5, -31.2, -8.0]
sort devolve:   None | original: [-31.2, -19.5, -8.0]
sorted de tupla vira lista: [1, 2, 3] <class 'list'>
sorted de dict: ['a', 'b']
reverse: [3, 2, 1]

sorted aceita qualquer iterável e devolve sempre uma lista nova; .sort() só existe em lista, ordena no lugar e devolve None — a convenção do Capítulo 18 que produz o erro niveis = niveis.sort().

Use .sort() quando a lista é sua e é grande (não duplica memória); sorted no resto dos casos, principalmente quando o original importa.

27.2 Como o key funciona

key é uma função de um argumento, aplicada a cada item. O que ordena é o resultado; o que volta na lista é o item original.

chamadas = []


def chave(item):
    chamadas.append(item)
    return item["nivel"]


LEITURAS = [
    {"onu": "onu-03", "nivel": -31.2},
    {"onu": "onu-01", "nivel": -19.5},
    {"onu": "onu-05", "nivel": -8.0},
]

ordenadas = sorted(LEITURAS, key=chave)
print("resultado:", [r["onu"] for r in ordenadas])
print("key chamada", len(chamadas), "vezes para", len(LEITURAS), "itens")
resultado: ['onu-03', 'onu-01', 'onu-05']
key chamada 3 vezes para 3 itens

Três itens, três chamadas — uma por item, não uma por comparação. Isso importa quando a chave é cara (uma consulta, uma conversão de data, uma normalização de texto): você paga n vezes, não n log n.

O operator do Capítulo 21 fornece as chaves mais comuns prontas:

from operator import itemgetter

LEITURAS = [
    ("onu-03", -31.2, "norte"),
    ("onu-01", -19.5, "sul"),
    ("onu-05", -8.0, "norte"),
    ("onu-02", -26.4, "sul"),
]
print("por nivel        :", [r[0] for r in sorted(LEITURAS, key=itemgetter(1))])
print("por olt e nivel  :", [r[0] for r in sorted(LEITURAS, key=itemgetter(2, 1))])
por nivel        : ['onu-03', 'onu-02', 'onu-01', 'onu-05']
por olt e nivel  : ['onu-03', 'onu-05', 'onu-02', 'onu-01']

itemgetter(2, 1) devolve a tupla (olt, nivel), e tupla se compara elemento a elemento — é assim que se ordena por vários critérios.

27.3 Direções diferentes no mesmo sort

reverse=True inverte tudo, o que não serve quando um critério é crescente e outro decrescente:

print("olt asc, nivel desc:", [r[0] for r in sorted(LEITURAS, key=lambda r: (r[2], -r[1]))])
print("reverse global   :", [r[0] for r in sorted(LEITURAS, key=itemgetter(2, 1), reverse=True)])
olt asc, nivel desc: ['onu-05', 'onu-03', 'onu-01', 'onu-02']
reverse global   : ['onu-01', 'onu-02', 'onu-05', 'onu-03']

Para número, o truque é o sinal negativo. Para texto, não há negativo — e aí entra a estabilidade.

27.4 Estabilidade

A ordenação do Python é estável: itens com chaves iguais mantêm a ordem em que estavam. Isso permite ordenar em várias passagens, da chave menos importante para a mais importante.

passo1 = sorted(LEITURAS, key=lambda r: r[1], reverse=True)
print("1) nivel desc:", [r[0] for r in passo1])
passo2 = sorted(passo1, key=lambda r: r[2])
print("2) depois olt:", [r[0] for r in passo2])

uma = sorted(LEITURAS, key=lambda r: (r[2], -r[1]))
print("uma passagem :", [r[0] for r in uma])
print("iguais?", [r[0] for r in passo2] == [r[0] for r in uma])
1) nivel desc: ['onu-05', 'onu-01', 'onu-02', 'onu-03']
2) depois olt: ['onu-05', 'onu-03', 'onu-01', 'onu-02']
uma passagem : ['onu-05', 'onu-03', 'onu-01', 'onu-02']
iguais? True

27.5 Quando os tipos não se comparam

sorted([3, "1", 2])
TypeError: '<' not supported between instances of 'str' and 'int'
sorted([1.0, None, 2.0])
TypeError: '<' not supported between instances of 'NoneType' and 'float'

Em Python 3, tipos diferentes não se comparam com < (no Python 2 comparavam, com resultado arbitrário — foi uma das correções mais importantes da migração). Duas saídas para o caso do None:

dados = [("a", -19.5), ("b", None), ("c", -31.2)]
print("None por ultimo:", sorted(dados, key=lambda p: (p[1] is None, p[1])))
print("None como -inf :", sorted(dados, key=lambda p: p[1] if p[1] is not None else float("-inf")))
None por ultimo: [('c', -31.2), ('a', -19.5), ('b', None)]
None como -inf : [('b', None), ('c', -31.2), ('a', -19.5)]

A primeira é a do Capítulo 24: o campo booleano separa os grupos e o None nunca chega a ser comparado, porque a comparação de tuplas para no primeiro campo que difere. A segunda troca o None por um valor extremo, e serve quando “sem leitura” deve contar como o pior caso.

Um par que se compara e às vezes surpreende:

print("bool ordena com int:", sorted([True, 0, False, 2]))
bool ordena com int: [0, False, True, 2]

False é 0 e True é 1, então eles se intercalam com os inteiros — e a estabilidade decide o empate entre 0 e False.

27.6 Ordenar objetos seus

Um objeto só é ordenável se souber responder a <. Há duas formas curtas:

from dataclasses import dataclass, field
from functools import total_ordering


@dataclass(order=True)
class Leitura:
    nivel: float
    onu: str = field(compare=False)


ls = [Leitura(-31.2, "onu-03"), Leitura(-19.5, "onu-01"), Leitura(-8.0, "onu-05")]
print("dataclass order=True:", [x.onu for x in sorted(ls)])
print("min:", min(ls).onu, "| max:", max(ls).onu)
dataclass order=True: ['onu-03', 'onu-01', 'onu-05']
min: onu-03 | max: onu-05

@dataclass(order=True) gera as quatro comparações a partir dos campos, na ordem em que foram declarados — por isso nivel vem primeiro, e onu está marcado com compare=False para não participar do desempate.

@total_ordering
class Porta:
    def __init__(self, numero):
        self.numero = numero

    def __eq__(self, outro):
        return self.numero == outro.numero

    def __lt__(self, outro):
        return self.numero < outro.numero

    def __repr__(self):
        return f"Porta({self.numero})"


ps = [Porta(10), Porta(2), Porta(1)]
print("total_ordering:", sorted(ps))
print("comparacoes derivadas:", Porta(1) <= Porta(2), Porta(10) >= Porta(2))
total_ordering: [Porta(1), Porta(2), Porta(10)]
comparacoes derivadas: True True

functools.total_ordering deriva <=, > e >= a partir de __eq__ e __lt__. Dataclasses e métodos especiais são os Volumes 7 e 8; aqui vale a regra: para ordenar uma vez, use key; para o objeto ter ordem natural, implemente a comparação.

27.7 Nem sempre é preciso ordenar

import heapq

niveis = [-19.5, -31.2, -8.0, -26.4, -33.1, -21.0]
print("3 piores heapq :", heapq.nsmallest(3, niveis))
print("3 piores sorted:", sorted(niveis)[:3])
print("min/max        :", min(niveis), max(niveis))
print("max com key    :", max([("onu-03", -31.2), ("onu-01", -19.5)], key=lambda r: r[1]))
print("min de vazio com default:", min([], default="nenhum"))
3 piores heapq : [-33.1, -31.2, -26.4]
3 piores sorted: [-33.1, -31.2, -26.4]
min/max        : -33.1 -8.0
max com key    : ('onu-01', -19.5)
min de vazio com default: nenhum

Para “os k melhores” com k pequeno e n grande, heapq.nsmallest/nlargest custam menos que ordenar tudo. Para um só, min/max com key — e com default= para não estourar ValueError na coleção vazia.

27.8 Quanto custa

import timeit

setup = "import random; dados = [random.random() for _ in range(20000)]"
a = timeit.timeit("sorted(dados)", setup=setup, number=50)
b = timeit.timeit("sorted(dados, key=lambda x: x)", setup=setup, number=50)
c = timeit.timeit("sorted(dados, key=abs)", setup=setup, number=50)
print(f"sem key        {a * 1000:8.1f} ms")
print(f"key=lambda x:x {b * 1000:8.1f} ms")
print(f"key=abs        {c * 1000:8.1f} ms")

import random

quase = sorted([random.random() for _ in range(20000)])
d = timeit.timeit("sorted(quase)", globals={"quase": quase}, number=50)
print(f"ja ordenado    {d * 1000:8.1f} ms  (Timsort aproveita a ordem existente)")
sem key            91.7 ms
key=lambda x:x    125.1 ms
key=abs           129.7 ms
ja ordenado         4.5 ms  (Timsort aproveita a ordem existente)

Três coisas: key custa (uma chamada por item, mesmo key=abs), então não passe uma que não precisa; e o algoritmo — o Timsort, criado por Tim Peters para o Python e depois adotado por Java e outras plataformas — detecta trechos já ordenados. Reordenar uma lista quase ordenada é vinte vezes mais barato que ordenar do zero, o que torna a estratégia de duas passagens muito menos cara do que parece.

27.9 Texto: maiúsculas e acentos

import unicodedata

nomes = ["Zebra", "abacaxi", "acido", "Agua", "ácido"]
print("padrao      :", sorted(nomes))
print("sem maiuscula:", sorted(nomes, key=str.casefold))


def sem_acento(t):
    d = unicodedata.normalize("NFD", t)
    return "".join(c for c in d if unicodedata.category(c) != "Mn")


print("dicionario  :", sorted(nomes, key=lambda s: (sem_acento(s).casefold(), s)))
padrao      : ['Agua', 'Zebra', 'abacaxi', 'acido', 'ácido']
sem maiuscula: ['abacaxi', 'acido', 'Agua', 'Zebra', 'ácido']
dicionario  : ['abacaxi', 'acido', 'ácido', 'Agua', 'Zebra']

A ordem padrão é por ponto de código: maiúsculas antes de minúsculas, e acentuadas depois de tudo. casefold resolve a primeira metade e deixa o ácido no fim; a chave do Capítulo 14, que remove acentos, resolve as duas. Para as regras completas de cada idioma, locale.strxfrm ou PyICU.

27.10 🐍 Jeito Pythônico

Ordene pelo valor, não pelo texto que o representa. Se o dado é número, converta na key.

key=, nunca cmp. O parâmetro de comparação par a par não existe mais em Python 3; functools.cmp_to_key é a ponte para código legado e é lento.

operator.itemgetter/attrgetter no lugar de lambda — mais rápido e mais claro, como no Capítulo 21.

# comum
sorted(registros, key=lambda r: (r["olt"], r["nivel"]))
# melhor
sorted(registros, key=itemgetter("olt", "nivel"))

Chave composta é uma tupla. Para inverter só um critério numérico, use o negativo; para texto, use duas passagens e conte com a estabilidade.

Dê nome à chave quando ela tiver lógica. key=gravidade documenta a regra de negócio; key=lambda r: (r[1], -r[3]) não.

min/max com key em vez de sorted(...)[0]. É uma passada em vez de n log n, e default= evita o ValueError da coleção vazia.

heapq.nlargest(k, ...) quando k é pequeno. Ordenar tudo para pegar três é desperdício.

Nunca compare tipos diferentes. Normalize antes, ou separe os grupos na própria chave.

Sobre versões:

  • Python 3.0 — cmp foi removido de sorted/sort; comparação entre tipos diferentes passou a ser TypeError; cmp_to_key entrou no functools como ponte.
  • Python 3.2 — functools.total_ordering.
  • Python 3.7 — @dataclass(order=True) (PEP 557).
  • Python 3.8 — min/max já aceitavam default=; key passou a ser aceito em mais funções da biblioteca padrão.
  • Python 3.11 — melhorias de desempenho no Timsort para listas de tipos homogêneos, com comparação especializada.

27.11 🧪 Laboratório

Objetivo: reproduzir a porta 10 antes da 2, medir quantas vezes o key é chamado, ver a estabilidade sustentando duas passagens e terminar com um ranking de gravidade com critérios em direções diferentes.

3. Ordem natural.

python -c "
import re
portas = ['porta-1', 'porta-10', 'porta-11', 'porta-2', 'porta-3']
def numero(nome):
    return int(nome.split('-')[1])
print(sorted(portas, key=numero))
def natural(texto):
    return [int(p) if p.isdigit() else p for p in re.split(r'(\d+)', texto)]
print(sorted(['a2', 'a10', 'b1', 'a1'], key=natural))
"
['porta-1', 'porta-2', 'porta-3', 'porta-10', 'porta-11']
['a1', 'a2', 'a10', 'b1']

A natural é a chave genérica: quebra o texto em pedaços de dígito e de não-dígito, e converte os de dígito em int. Funciona para qualquer mistura de texto e número.

4. sorted contra .sort().

python -c "
niveis = [-19.5, -31.2, -8.0]
copia = sorted(niveis)

from dataclasses import dataclass, field
from functools import total_ordering


@dataclass(order=True)

    nivel: float
    onu: str = field(compare=False)

@total_ordering
class Porta:
    def __init__(self, numero):
        self.numero = numero

    def __eq__(self, outro):
        return self.numero == outro.numero

    def __lt__(self, outro):
        return self.numero < outro.numero

    def __repr__(self):
        return f"Porta({self.numero})"


ps = [Porta(10), Porta(2), Porta(1)]
print("total_ordering:", sorted(ps))
print("comparacoes derivadas:", Porta(1) <= Porta(2), Porta(10) >= Porta(2))

13. O ranking de gravidade. Crie ranking.py:

"""Ranking de ONUs com chave composta, estabilidade e criterios mistos."""

from operator import itemgetter

LEITURAS = [
    {"onu": "porta-10", "olt": "norte", "nivel": -31.2, "erros": 4},
    {"onu": "porta-2", "olt": "norte", "nivel": -19.5, "erros": 0},
    {"onu": "porta-1", "olt": "sul", "nivel": -31.2, "erros": 12},
    {"onu": "porta-11", "olt": "sul", "nivel": -8.0, "erros": 0},
    {"onu": "porta-3", "olt": "norte", "nivel": -26.4, "erros": 4},
]


def numero_da_porta(registro):
    return int(registro["onu"].split("-")[1])


def gravidade(registro):
    """Pior primeiro: nivel mais baixo, e desempate por mais erros."""
    return (registro["nivel"], -registro["erros"])


if __name__ == "__main__":
    print("ordem crua (lexicografica):")
    print("  ", [r["onu"] for r in sorted(LEITURAS, key=itemgetter("onu"))])

    print("ordem natural das portas:")
    print("  ", [r["onu"] for r in sorted(LEITURAS, key=numero_da_porta)])

    print("por gravidade:")
    for r in sorted(LEITURAS, key=gravidade):
        print(f"   {r['onu']:<9} {r['nivel']:>7.1f}  {r['erros']:>2} erros  {r['olt']}")

    print("por OLT, e dentro dela por gravidade:")
    for r in sorted(LEITURAS, key=lambda x: (x["olt"], *gravidade(x))):
        print(f"   {r['olt']:<6} {r['onu']:<9} {r['nivel']:>7.1f}")

    print("top 2 mais graves:", [r["onu"] for r in sorted(LEITURAS, key=gravidade)[:2]])
    print("melhor leitura:", max(LEITURAS, key=itemgetter("nivel"))["onu"])

Escrever a regra de negócio numa função com nome e reaproveitá-la em duas ordenações diferentes é o que separa key=gravidade de uma lambda copiada em quatro lugares.

27.12 Resumo

  • sorted aceita qualquer iterável e devolve lista nova; .sort() só em lista, no lugar, devolvendo None.
  • String se compara caractere a caractere: "porta-10" < "porta-2". Ordenar número guardado como texto exige converter na key.
  • key é aplicada uma vez por item (decorate-sort-undecorate), então chave cara é barata. O que ordena é a chave; o que volta é o item.
  • Chave composta é uma tupla; reverse=True inverte tudo. Para direções mistas, negativo em número ou duas passagens.
  • A ordenação é estável: ordene da chave menos importante para a mais importante.
  • Tipos diferentes não se comparam em Python 3. Para None, use (x is None, x) na chave ou substitua por um extremo.
  • Para ordem natural de objetos, @dataclass(order=True) ou __lt__ mais functools.total_ordering; para ordenar uma vez, key basta.
  • min/max com key e default=, e heapq.nsmallest/nlargest para os k melhores, evitam ordenar tudo.
  • O Timsort aproveita trechos já ordenados: reordenar lista quase ordenada é ordens de grandeza mais barato.
