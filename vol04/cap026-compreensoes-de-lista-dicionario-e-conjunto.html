26  Compreensões de lista, dicionário e conjunto

O relatório precisa de um índice de ONUs por OLT. Uma compreensão de dicionário resolve numa linha:

LEITURAS = [
    {"onu": "onu-01", "olt": "norte", "nivel": -19.5},
    {"onu": "onu-02", "olt": "norte", "nivel": -31.2},
    {"onu": "onu-03", "olt": "sul", "nivel": -26.4},
    {"onu": "onu-04", "olt": "sul", "nivel": -8.0},
    {"onu": "onu-05", "olt": "norte", "nivel": -33.1},
]

POR_OLT = {r["olt"]: r["onu"] for r in LEITURAS}
print(f"{len(LEITURAS)} leituras viraram {len(POR_OLT)} registros")
print(POR_OLT)
5 leituras viraram 2 registros
{'norte': 'onu-05', 'sul': 'onu-04'}

Cinco leituras entraram, duas saíram. A compreensão fez exatamente o que foi pedida: para cada leitura, atribuiu POR_OLT[olt] = onu. Como três leituras têm olt == "norte", a terceira sobrescreveu as duas anteriores — e sobrou a última.

Não houve erro, não houve aviso, e o dicionário resultante é perfeitamente válido. Só está errado: norte tem três ONUs, e o índice diz que tem uma.

Compreensão de dicionário só é segura quando a chave é única. Quando não é, o que você quer é agrupar:

from collections import defaultdict

grupos = defaultdict(list)
for r in LEITURAS:
    grupos[r["olt"]].append(r["onu"])
print(dict(grupos))
{'norte': ['onu-01', 'onu-02', 'onu-05'], 'sul': ['onu-03', 'onu-04']}

Indexar por onu, que é único, é o uso correto da compreensão — e aí os cinco entram e cinco saem.

Este capítulo é sobre a construção mais característica do Python: o que ela faz, em que ordem lê, quando substitui um laço com vantagem e quando é melhor não usar.

26.1 A forma básica

niveis = [-19.5, -31.2, -8.0, -26.4]

quadrados = []
for n in niveis:
    quadrados.append(abs(n))
print("laco       :", quadrados)
print("compreensao:", [abs(n) for n in niveis])
laco       : [19.5, 31.2, 8.0, 26.4]
compreensao: [19.5, 31.2, 8.0, 26.4]

A compreensão é o for com append escrito de trás para frente: primeiro o que vai para a lista, depois de onde vem.

O if no fim filtra; o condicional do Capítulo 15 no começo mapeia todos:

print("com filtro :", [abs(n) for n in niveis if n < -20])
print("com ternario:", ["critico" if n < -28 else "ok" for n in niveis])
print("os dois    :", ["C" if n < -28 else "A" for n in niveis if n < -20])
com filtro : [31.2, 26.4]
com ternario: ['ok', 'critico', 'ok', 'ok']
os dois    : ['C', 'A']

A distinção é a que mais confunde no começo: if depois do for decide se o item entra; if/else antes do for decide qual valor entra. O else é o desempate visual — filtro não tem else, e não pode ter.

26.2 As quatro formas

print("lista :", [n * 2 for n in range(4)])
print("set   :", {n % 3 for n in range(8)})
print("dict  :", {n: n * n for n in range(4)})
print("gerador:", (n * 2 for n in range(4)))
print("tupla nao existe:", tuple(n * 2 for n in range(4)))
print("invertendo dict:", {v: k for k, v in {"a": 1, "b": 2}.items()})
lista : [0, 2, 4, 6]
set   : {0, 1, 2}
dict  : {0: 0, 1: 1, 2: 4, 3: 9}
gerador: <generator object <genexpr> at 0x7723c998aa80>
tupla nao existe: (0, 2, 4, 6)
invertendo dict: {1: 'a', 2: 'b'}

O conjunto deduplicou sozinho (range(8) % 3 produz oito valores e três elementos). E (...) não é “compreensão de tupla”: é uma expressão geradora, que não construiu nada — só devolveu um objeto que sabe produzir os valores quando pedirem.

A inversão de dicionário na última linha é um idioma muito usado, e sofre da mesma armadilha da abertura: se dois valores forem iguais, o dicionário invertido perde entradas.

26.3 Expressão geradora

import sys

lista = [n for n in range(100000)]
gerador = (n for n in range(100000))
print("lista  :", sys.getsizeof(lista), "bytes")
print("gerador:", sys.getsizeof(gerador), "bytes")
lista  : 800984 bytes
gerador: 192 bytes

Oitocentos kilobytes contra cento e noventa e dois bytes. O gerador não guarda os valores: guarda como produzi-los.

Quando o resultado vai direto para uma função que consome iterável, os colchetes são desperdício:

print("soma com colchetes:", sum([n for n in range(10)]))
print("soma sem colchetes:", sum(n for n in range(10)))
print("any curto-circuito:", any(n > 1 for n in range(1000000)))
soma com colchetes: 45
soma sem colchetes: 45
any curto-circuito: True

A versão com colchetes constrói uma lista inteira só para somá-la e jogá-la fora. E o any mostra o outro ganho: ele parou no terceiro item, sem produzir os outros 999.997.

Quando a expressão geradora é o único argumento, os parênteses dela podem ser omitidos — é o que torna sum(n for n in ...) legal.

O preço é o do Capítulo 16: gerador é de uma passada só.

g = (n for n in range(3))
print("primeira passada:", list(g))
print("segunda  passada:", list(g))
primeira passada: [0, 1, 2]
segunda  passada: []

26.4 Compreensão aninhada

Dois for na mesma compreensão achatam uma estrutura, na mesma ordem em que os laços apareceriam:

MATRIZ = [[1, 2, 3], [4, 5, 6]]

achatada = []
for linha in MATRIZ:
    for valor in linha:
        achatada.append(valor)
print("laco aninhado :", achatada)
print("compreensao   :", [valor for linha in MATRIZ for valor in linha])
laco aninhado : [1, 2, 3, 4, 5, 6]
compreensao   : [1, 2, 3, 4, 5, 6]

Escrever na ordem invertida é o erro clássico — e, dependendo do que existe no escopo, ele não falha:

print([valor for valor in linha for linha in MATRIZ])
[4, 4, 5, 5, 6, 6]

Num arquivo limpo isso seria NameError: name 'linha' is not defined. Aqui não foi, porque o laço for linha in MATRIZ das linhas anteriores vazou a variável — o comportamento do Capítulo 20 — e linha ainda valia [4, 5, 6]. O resultado é lixo silencioso: seis elementos, todos errados.

É o argumento mais forte para não reaproveitar nomes de variável de laço, e para desconfiar de compreensão aninhada que “quase” funciona.

A compreensão de compreensão é outra coisa, e produz aninhamento em vez de achatar:

print("matriz de matriz:", [[v * 10 for v in linha] for linha in MATRIZ])
print("com filtro no meio:", [v for linha in MATRIZ for v in linha if v % 2 == 0])
matriz de matriz: [[10, 20, 30], [40, 50, 60]]
com filtro no meio: [2, 4, 6]

Foi a compreensão de compreensão que resolveu o [[0] * 3] * 3 do Capítulo 22: cada volta do for externo executa o [...] interno de novo, produzindo um objeto novo.

26.5 Morsa em compreensão

O := do Capítulo 15 resolve o caso “filtrar pelo resultado de uma função e usar esse resultado”:

import re

linhas = ["onu-01 nivel=-19.5", "onu-02 sem leitura", "onu-03 nivel=-31.2"]
padrao = re.compile(r"nivel=(-?\d+\.\d+)")
print([float(m.group(1)) for linha in linhas if (m := padrao.search(linha))])
[-19.5, -31.2]

Sem ele, seriam duas buscas por linha — uma no filtro e outra na expressão de saída.

26.6 Escopo próprio

n = "valor de fora"
quadrados = [n * n for n in range(3)]
print(quadrados, "| n continua:", n)
[0, 1, 4] | n continua: valor de fora

A variável da compreensão vive num escopo próprio e não vaza — ao contrário do for de bloco, como o Capítulo 20 mostrou. É por isso que a compreensão é mais segura que o laço equivalente num arquivo longo, e é também por isso que o erro da compreensão aninhada acima só aconteceu por causa de um for de bloco anterior.

26.7 Desempenho

import timeit

setup = "dados = list(range(2000))"
a = timeit.timeit(
    """
r = []
for n in dados:
    r.append(n * 2)
""",
    setup=setup,
    number=2000,
)
b = timeit.timeit("[n * 2 for n in dados]", setup=setup, number=2000)
c = timeit.timeit("list(map(lambda n: n * 2, dados))", setup=setup, number=2000)
print(f"laco com append  {a * 1000:8.1f} ms")
print(f"compreensao      {b * 1000:8.1f} ms")
print(f"map com lambda   {c * 1000:8.1f} ms")
laco com append      76.4 ms
compreensao          58.5 ms
map com lambda      128.9 ms

A compreensão ganha do laço porque não paga a busca do método append a cada volta, e ganha do map com lambda porque não paga uma chamada de função Python por item — o mesmo resultado do Capítulo 21. Desde o Python 3.12 a vantagem aumentou: as compreensões deixaram de criar um quadro de função próprio (PEP 709).

Dito isso, a razão para preferir compreensão é legibilidade. Ganhar 25% num laço que roda mil vezes não muda nada; escrever a intenção em uma linha, sim.

26.8 Quando não usar

# ilegivel: tudo numa expressao so
ruim = {
    r["olt"]: [p for p in r["portas"]]
    for r in REGISTROS
    if r["nivel"] is not None and r["portas"]
}
# legivel: laco explicito, com nome para cada passo
bom = defaultdict(list)
for r in REGISTROS:
    if r["nivel"] is None:
        continue
    bom[r["olt"]].extend(r["portas"])
ruim: {'norte': [1, 2], 'sul': [3]}
bom : {'norte': [1, 2], 'sul': [3]}

Os dois dão o mesmo resultado neste conjunto de dados — e o de cima ainda esconde o bug da chave repetida. Quatro sinais de que a compreensão passou do ponto:

  1. Não cabe em uma linha de forma legível (nem quebrada em duas ou três).
  2. Tem efeito colateral. [print(x) for x in itens] constrói uma lista de None para jogar fora; isso é um laço disfarçado.
  3. Passa de dois for.
  4. Precisa de try/except. Compreensão não trata exceção; se um item pode falhar, o laço é o lugar.

26.9 🐍 Jeito Pythônico

Compreensão para transformar e filtrar; laço para efeito colateral. Se o resultado é descartado, é laço.

# antipadrão
[salvar(r) for r in registros]
# pythônico
for r in registros:
    salvar(r)

Compreensão de dicionário só com chave única. Para agrupar, defaultdict(list) ou itertools.groupby.

Sem colchetes dentro de sum, any, all, min, max e join. A expressão geradora não materializa a lista e permite curto-circuito.

# antipadrão
total = sum([r["nivel"] for r in leituras if r["nivel"]])
# pythônico
total = sum(r["nivel"] for r in leituras if r["nivel"])

if no fim filtra, if/else no começo mapeia. Nunca são a mesma coisa.

Dois for no máximo, e sempre na ordem dos laços equivalentes.

Não reaproveite o nome da variável do laço — a compreensão aninhada errada pode encontrar o nome vazado e produzir lixo em vez de erro.

list(dict.fromkeys(x)) continua sendo o jeito de deduplicar com ordem — não tente fazer isso com compreensão e um conjunto auxiliar; fica mais longo e mais lento.

Sobre versões:

  • Python 3.0 — compreensões de conjunto e de dicionário passaram a existir; a variável da compreensão ganhou escopo próprio.
  • Python 3.6 — compreensões assíncronas, com async for (PEP 530).
  • Python 3.8 — operador morsa dentro de compreensão (PEP 572).
  • Python 3.12 — compreensões de lista, dicionário e conjunto deixaram de criar quadro de função próprio, ficando até duas vezes mais rápidas (PEP 709).

import sys

11. Quando parar. Crie ilegivel.py:

REGISTROS = [
    {"onu": "onu-01", "olt": "norte", "nivel": -19.5, "portas": [1, 2]},
    {"onu": "onu-02", "olt": "sul", "nivel": -31.2, "portas": [3]},
    {"onu": "onu-03", "olt": "norte", "nivel": None, "portas": []},
]

# ilegivel: tudo numa expressao so
ruim = {r["olt"]: [p for p in r["portas"]] for r in REGISTROS if r["nivel"] is not None and r["portas"]}

# legivel: laco explicito, com nome para cada passo
from collections import defaultdict

bom = defaultdict(list)
for r in REGISTROS:
    if r["nivel"] is None:
        continue
    bom[r["olt"]].extend(r["portas"])

print("ruim:", ruim)
print("bom :", dict(bom))

"""Relatorio de varredura escrito com compreensoes onde elas cabem."""

LEITURAS = [
    {"onu": "onu-01", "olt": "norte", "nivel": -19.5},
    {"onu": "onu-02", "olt": "norte", "nivel": -31.2},
    {"onu": "onu-03", "olt": "sul", "nivel": -26.4},
    {"onu": "onu-04", "olt": "sul", "nivel": None},
    {"onu": "onu-05", "olt": "norte", "nivel": -33.1},
]

CRITICO = -28.0

# indice por chave unica: aqui a compreensao de dicionario e segura
POR_ONU = {r["onu"]: r for r in LEITURAS}

# conjunto de OLTs distintas
OLTS = {r["olt"] for r in LEITURAS}

# so as medidas, ja filtradas
MEDIDAS = [r["nivel"] for r in LEITURAS if r["nivel"] is not None]

# rotulo por ONU, com ternario
FAIXA = {
    r["onu"]: ("sem leitura" if r["nivel"] is None
               else "critico" if r["nivel"] < CRITICO else "normal")
    for r in LEITURAS
}

if __name__ == "__main__":
    print("indice:", len(POR_ONU), "ONUs |", "olts:", sorted(OLTS))
    print("medidas:", MEDIDAS)
    print("media:", f"{sum(MEDIDAS) / len(MEDIDAS):.2f}")
    print("faixas:", FAIXA)

    criticas = [onu for onu, faixa in FAIXA.items() if faixa == "critico"]
    print("criticas:", criticas)

    # gerador: nao materializa nada
    print("alguma critica?", any(f == "critico" for f in FAIXA.values()))
    print("quantas medidas abaixo de -25:", sum(1 for n in MEDIDAS if n < -25))

    por_olt = {
        olt: [r["onu"] for r in LEITURAS if r["olt"] == olt]
        for olt in sorted(OLTS)
    }
    print("por olt:", por_olt)

Cada compreensão faz uma coisa e tem um nome. O POR_ONU é seguro porque onu é único; o por_olt do fim resolve o agrupamento sem defaultdict, ao custo de percorrer as leituras uma vez por OLT — aceitável para cinco registros e inaceitável para cinquenta mil, onde o defaultdict de uma passada volta a ser a resposta.

O sum(1 for n in MEDIDAS if n < -25) é o idioma para contar sem construir lista: um gerador de uns, somado.

26.11 Resumo

  • Compreensão é o laço com append reescrito com a saída na frente: [saída for alvo in iterável if filtro]. A ordem de execução é percorrer, filtrar, produzir.
  • if no fim filtra; if/else no começo mapeia todos. O else distingue os dois.
  • Trocar [] por {} com dois-pontos dá dicionário, sem dois-pontos dá conjunto, e () dá uma expressão geradora, que não constrói nada.
  • Compreensão de dicionário só é segura com chave única — chave repetida descarta silenciosamente as anteriores. Para agrupar, defaultdict(list).
  • Gerador ocupa bytes em vez de megabytes, permite curto-circuito em any/all e é de uma passada só. Dentro de sum, any, all e join, dispense os colchetes.
  • Em compreensão aninhada, o primeiro for é o laço mais externo. A ordem invertida dá NameError — ou lixo silencioso, se o nome tiver vazado de um laço anterior.
  • A variável da compreensão tem escopo próprio e não vaza; a do for de bloco vaza.
  • Compreensão é mais rápida que laço com append e que map com lambda, mas a razão para usá-la é legibilidade. Efeito colateral, três for, try ou linha ilegível são sinais de que o laço é a resposta.
