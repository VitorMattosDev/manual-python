23  Tuplas, empacotamento e desempacotamento

O script de sincronização tem uma constante no topo com a lista de OLTs a visitar. Hoje só existe uma, e o autor deixou os parênteses ali para não esquecer de acrescentar as outras depois:

DESTINOS = ("olt-norte")

print(type(DESTINOS), len(DESTINOS))
for d in DESTINOS:
    print("  sincronizando", d)
<class 'str'> 9
  sincronizando o
  sincronizando l
  sincronizando t
  sincronizando -
  sincronizando n
  sincronizando o
  sincronizando r
  sincronizando t
  sincronizando e

Nove sincronizações, uma para cada letra. DESTINOS não é uma tupla de um elemento: é uma string, e os parênteses ali eram só agrupamento de expressão, como em (2 + 3) * 4.

A correção é uma vírgula:

print(type(("olt-norte")), type(("olt-norte",)), type(()))
print(len(("olt-norte",)))
<class 'str'> <class 'tuple'> <class 'tuple'>
1

O que cria a tupla é a vírgula, não o parêntese. Essa é a frase que o capítulo inteiro desdobra — e a exceção é a tupla vazia, (), que não tem onde pôr vírgula.

23.1 A vírgula é a construtora

sem_parenteses = "onu-01", -19.5, "ativa"
print(sem_parenteses, type(sem_parenteses))


def devolve():
    return 1, 2


print(devolve(), type(devolve()))
print(divmod(17, 5))
('onu-01', -19.5, 'ativa') <class 'tuple'>
(1, 2) <class 'tuple'>
(3, 2)

Nenhuma dessas três linhas tem parênteses de tupla, e as três produzem tuplas. É por isso que o “devolver vários valores” do Capítulo 18 funciona: return 1, 2 empacota numa tupla antes de sair.

23.2 Imutável — e só na superfície

t = ("onu-01", -19.5)
t[1] = -20.0
TypeError: 'tuple' object does not support item assignment

Não há append, remove, sort nem atribuição por índice. O que existe é o que não modifica: indexação, fatiamento, in, len, count, index, + e * (que criam tuplas novas).

Mas a imutabilidade é rasa, exatamente como a cópia do Capítulo 22:

com_lista = ("onu-01", [1, 2])
com_lista[1].append(3)
print("a tupla nao mudou, a lista sim:", com_lista)
a tupla nao mudou, a lista sim: ('onu-01', [1, 2, 3])

A tupla continua guardando exatamente as mesmas duas referências. O que mudou foi o objeto do outro lado da segunda referência.

Isso tem uma consequência prática imediata: hashabilidade.

print("hash de tupla simples:", hash(("onu-01", -19.5)))
hash(com_lista)
hash de tupla simples: -8596631426215206173
TypeError: unhashable type: 'list'

Uma tupla é hashável se e somente se todos os elementos dela forem. É a razão de a tupla poder ser chave de dicionário e a lista não — e de uma tupla com lista dentro também não poder.

23.3 Empacotar e desempacotar

Empacotamento é o que a vírgula faz; desempacotamento é o inverso, do lado esquerdo da atribuição:

onu, nivel, estado = ("onu-01", -19.5, "ativa")
print(onu, nivel, estado)

a, b = 1, 2
a, b = b, a
print("troca:", a, b)

(nome, (x, y)) = ("ponto", (3, 4))
print("aninhado:", nome, x, y)

_, nivel, _ = ("onu-01", -19.5, "ativa")
print("so o que interessa:", nivel)
onu-01 -19.5 ativa
troca: 2 1
aninhado: ponto 3 4
so o que interessa: -19.5

A troca a, b = b, a funciona porque o lado direito é avaliado inteiro antes de qualquer atribuição: monta-se a tupla (2, 1) e só depois ela é desmontada. Não há variável temporária, e não há ordem que atrapalhe.

O _ é convenção, não sintaxe: é um nome comum, que a comunidade usa para “não me interessa”. Ele pode se repetir, e fica valendo o último valor atribuído.

O desempacotamento exige quantidade exata:

registros = [("onu-01", -19.5), ("onu-02", -31.2, "critica")]
for r in registros:
    try:
        onu, nivel = r
        print(f"{onu}: {nivel}")
    except ValueError as e:
        print("ValueError:", e)

try:
    a, b, c = (1, 2)
except ValueError as e:
    print("ValueError:", e)
onu-01: -19.5
ValueError: too many values to unpack (expected 2)
ValueError: not enough values to unpack (expected 3, got 2)

As duas mensagens são precisas e dizem os dois números. Quando os registros têm tamanho variável — o caso do CSV com coluna opcional —, a saída é o desempacotamento estendido.

23.4 Desempacotamento estendido

Desde o Python 3.0 (PEP 3132), um alvo pode levar * e absorver o resto:

primeiro, *resto = [10, 20, 30, 40]
print(primeiro, resto, type(resto))

*inicio, ultimo = [10, 20, 30, 40]
print(inicio, ultimo)

a, *meio, z = "abcdef"
print(a, meio, z)

so_um, *nada = [7]
print(so_um, nada)
10 [20, 30, 40] <class 'list'>
[10, 20, 30] 40
a ['b', 'c', 'd', 'e'] f
7 []

Três coisas importantes: o alvo com * recebe sempre uma lista (mesmo desempacotando uma tupla ou uma string), pode ficar vazio sem erro, e só pode haver um por alvo.

O uso mais frequente é separar cabeçalho de corpo:

cabecalho, *linhas = "onu;nivel\nonu-01;-19.5\nonu-02;-31.2".splitlines()
print(cabecalho, "|", linhas)
onu;nivel | ['onu-01;-19.5', 'onu-02;-31.2']

23.5 Desempacotar no laço

Combinado com o for do Capítulo 16, o desempacotamento elimina índices:

LEITURAS = [("onu-01", -19.5, "norte"), ("onu-02", -31.2, "sul")]
for onu, nivel, olt in LEITURAS:
    print(f"{onu:<8} {nivel:>7.1f} {olt}")
for i, (onu, nivel, olt) in enumerate(LEITURAS, start=1):
    print(i, onu, olt)
onu-01     -19.5 norte
onu-02     -31.2 sul
1 onu-01 norte
2 onu-02 sul

O i, (onu, nivel, olt) é desempacotamento aninhado: o enumerate produz (índice, item) e o item é desmontado no mesmo passo.

23.6 Tupla como chave

Como tuplas de imutáveis são hasháveis, elas são a chave composta natural:

CACHE = {}
CACHE[("olt-norte", 1, 3)] = -19.5
CACHE[("olt-sul", 2, 1)] = -31.2
print(CACHE[("olt-norte", 1, 3)])
print(sorted(CACHE))
CACHE[["olt-norte", 1, 3]] = 0
-19.5
[('olt-norte', 1, 3), ('olt-sul', 2, 1)]
TypeError: unhashable type: 'list'

Isso é o que permite indexar por (OLT, placa, porta), por (linha, coluna), por (data, produto) — sem inventar uma string concatenada com separador, que sempre acaba encontrando um separador dentro do dado.

23.7 Tupla ou lista?

Tecnicamente, a diferença é a mutabilidade. Na prática, a convenção é semântica:

  • Tupla é registro: posições com significados diferentes, quantidade fixa. (onu, nivel, olt), (x, y), (host, porta). Desempacotar faz sentido.
  • Lista é coleção: itens com o mesmo significado, quantidade variável. [onu1, onu2, onu3]. Percorrer faz sentido.

Quando o registro tem mais de três campos, ou quando você se pega contando posições para lembrar o que é r[3], a tupla já passou do ponto: a resposta é NamedTuple ou dataclass, do Volume 7.

Há um ganho de desempenho, e ele é secundário:

import sys
import timeit

lista = [1, 2, 3, 4, 5]
tupla = (1, 2, 3, 4, 5)
print("lista:", sys.getsizeof(lista), "bytes | tupla:", sys.getsizeof(tupla), "bytes")
tl = timeit.timeit("[1, 2, 3, 4, 5]", number=2_000_000)
tt = timeit.timeit("(1, 2, 3, 4, 5)", number=2_000_000)
print(f"criar lista {tl:.3f}s | criar tupla {tt:.3f}s")
lista: 104 bytes | tupla: 80 bytes
criar lista 0.053s | criar tupla 0.019s

Menor porque não precisa reservar espaço para crescer, e quase três vezes mais rápida de criar por um motivo específico:

import dis

dis.dis("x = (1, 2, 3)")
  0           RESUME                   0

  1           LOAD_CONST               0 ((1, 2, 3))
              STORE_NAME               0 (x)
              RETURN_CONST             1 (None)

A tupla de constantes é montada na compilação e vira uma constante única no bytecode. Uma lista precisa ser construída em tempo de execução, elemento a elemento, toda vez — porque alguém pode modificá-la depois.

23.8 🐍 Jeito Pythônico

Vírgula final em tupla de um elemento, e de preferência com parênteses: ("olt-norte",). Sem eles, x = "olt-norte", é fácil de ler como um erro de digitação.

Desempacote em vez de indexar. onu, nivel = registro diz o que cada posição é; registro[0] e registro[1] não dizem nada.

# antipadrão
for r in leituras:
    print(r[0], r[1] * 2)
# pythônico
for onu, nivel in leituras:
    print(onu, nivel * 2)

Troque com a, b = b, a. Sem temporária, e é o idioma que todo mundo reconhece.

*resto no lugar de fatiar. primeiro, *resto = seq é mais claro que seq[0] e seq[1:], e falha alto se a sequência estiver vazia.

Tupla para chave composta e para retorno de função. Não concatene strings com separador para formar chave — o separador sempre aparece dentro de um dado real.

Tupla como padrão de parâmetro é seguro — é imutável, então não sofre o problema do Capítulo 19. def f(destinos=()) é legítimo.

A partir de três campos, considere NamedTuple. Uma NamedTuple continua sendo tupla (desempacota, é hashável, é imutável) e ganha nomes:

# ilegível na segunda leitura
def alerta(r):
    return f"{r[0]} em {r[3]}"

Anote como tuple[str, float] para registro e tuple[str, ...] para coleção. As duas formas dizem coisas diferentes ao verificador de tipos: a primeira é “exatamente dois campos”, a segunda é “qualquer quantidade, todos str”.

Sobre versões:

  • Python 3.0 — desempacotamento estendido com * no alvo (PEP 3132).
  • Python 3.5 — * e ** em literais e chamadas: (*a, *b), f(*a, **b) (PEP 448).
  • Python 3.8 — f"{x=}", que imprime nome e valor e é muito usado com tupla desempacotada.
  • Python 3.9 — tuple[str, float] na anotação, sem typing.Tuple (PEP 585).
  • Python 3.10 — o match do Capítulo 17 casa tuplas por tamanho e posição, o que é desempacotamento com teste embutido.

13. O índice de enlaces. Crie enlace.py:

"""Leituras como tuplas: registro fixo, chave composta e desempacotamento."""

from collections import defaultdict

# (olt, placa, porta) -> (onu, nivel_dbm)
ENLACES = {
    ("olt-norte", 1, 1): ("onu-01", -19.5),
    ("olt-norte", 1, 3): ("onu-02", -31.2),
    ("olt-norte", 2, 1): ("onu-03", -26.4),
    ("olt-sul", 1, 1): ("onu-04", -8.0),
    ("olt-sul", 1, 2): ("onu-05", -33.1),
}

CRITICO = -28.0


def por_olt(enlaces):
    """Agrupa os enlaces por OLT, preservando a chave completa."""
    grupos = defaultdict(list)
    for (olt, placa, porta), (onu, nivel) in enlaces.items():
        grupos[olt].append((placa, porta, onu, nivel))
    return grupos


def criticos(enlaces):
    return [
        (olt, placa, porta, onu, nivel)
        for (olt, placa, porta), (onu, nivel) in enlaces.items()
        if nivel < CRITICO
    ]


if __name__ == "__main__":
    for olt, itens in por_olt(ENLACES).items():
        print(f"{olt}:")
        for placa, porta, onu, nivel in sorted(itens):
            marca = "  <-- critico" if nivel < CRITICO else ""
            print(f"  placa {placa} porta {porta}  {onu}  {nivel:>7.1f}{marca}")

    achados = criticos(ENLACES)
    print(f"\n{len(achados)} criticos")
    pior, *outros = sorted(achados, key=lambda r: r[4])
    print("pior:", pior)
    print("demais:", [r[3] for r in outros])

    chave = ("olt-norte", 1, 3)
    onu, nivel = ENLACES[chave]
    print(f"consulta por chave composta {chave}: {onu} em {nivel} dBm")

Três usos de tupla numa tela só: chave composta no dicionário, registro no valor, e o desempacotamento aninhado for (olt, placa, porta), (onu, nivel) in enlaces.items(), que desmonta chave e valor no mesmo cabeçalho de laço. O sorted(itens) também é tupla trabalhando: ordenou por placa e, dentro dela, por porta, sem key nenhuma.

E repare no r[4] do key=: cinco campos posicionais já é demais para memorizar. É exatamente aqui que a tupla pede para virar NamedTuple.

23.10 Resumo

  • A vírgula cria a tupla, não o parêntese. ("x") é string; ("x",) é tupla de um; () é a tupla vazia.
  • Tupla é imutável na superfície: as referências são fixas, os objetos apontados podem mudar. Uma tupla é hashável só se todos os elementos forem.
  • Empacotar é a vírgula; desempacotar é o alvo múltiplo. a, b = b, a troca sem temporária porque o lado direito é avaliado inteiro antes.
  • Quantidade errada dá ValueError com mensagem precisa; *alvo absorve o resto numa lista, pode ficar vazio e só pode aparecer uma vez.
  • Desempacotamento aninhado funciona em cabeçalho de for e com enumerate, eliminando índices.
  • Tupla de imutáveis é a chave composta natural de dicionário — melhor que string concatenada com separador.
  • Convenção: tupla é registro de campos heterogêneos e fixos; lista é coleção homogênea e variável. A partir de três campos, NamedTuple.
  • Tupla ocupa menos memória e é mais rápida de criar, porque tuplas de constantes são montadas na compilação e viram uma constante do bytecode.
