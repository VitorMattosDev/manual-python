25  Conjuntos e operações de conjunto

O coletor precisa ignorar as ONUs que estão na lista de bloqueio. A constante fica no topo do arquivo, vazia por enquanto — a equipe preenche conforme os chamados aparecem:

BLOQUEADAS = {}

LEITURAS = ["onu-01", "onu-02", "onu-03", "onu-05"]

print("tipo de BLOQUEADAS:", type(BLOQUEADAS))
for onu in LEITURAS:
    if onu in BLOQUEADAS:
        print(f"  {onu}: bloqueada, ignorando")
        continue
    print(f"  {onu}: processando")
tipo de BLOQUEADAS: <class 'dict'>
  onu-01: processando
  onu-02: processando
  onu-03: processando
  onu-05: processando

Enquanto a constante estiver vazia, tudo funciona — e é essa a parte perigosa. {} não é um conjunto vazio: é um dicionário vazio. No dia em que alguém escrever BLOQUEADAS = {"onu-02", "onu-05"} o código passa a funcionar, e ninguém nunca descobre que a versão anterior nunca teria bloqueado nada, porque in num dicionário testa chaves — e o dicionário estava vazio.

Pior: se alguém “corrigir” acrescentando com BLOQUEADAS["onu-02"] = True, o filtro passa a funcionar por acidente, e a estrutura errada fica no código.

O conjunto vazio se escreve set():

print(type({}), type(set()), type({1, 2}), type({"a": 1}))
print(set(), len(set()))
<class 'dict'> <class 'set'> <class 'set'> <class 'dict'>
set() 0

As chaves servem aos dois tipos, e o desempate é o conteúdo: com : é dicionário, sem : é conjunto, e vazio é dicionário — porque o dicionário chegou primeiro na linguagem.

Este capítulo é sobre a estrutura que responde a duas perguntas muito frequentes em tempo constante: este item já apareceu? e o que estes dois grupos têm em comum?

25.1 Um conjunto é um dicionário sem valores

Por dentro é a mesma tabela hash do Capítulo 24, guardando só as chaves. Daí vêm as três propriedades:

  • Elementos únicos. Inserir de novo não faz nada.
  • Elementos hasháveis. Vale a mesma regra da chave de dicionário.
  • Sem ordem. Não há índice, não há fatiamento, e a ordem de iteração não é a de inserção.
print(set("abracadabra"))
print(set([1, 2, 2, 3]), set(("a", "a")))
print(bool(set()), bool({0}))
{'r', 'c', 'd', 'a', 'b'}
{1, 2, 3} {'a'}
False True

A primeira linha sai em outra ordem a cada execução: o Python aleatoriza o hash de strings entre processos, justamente para que ninguém escreva código que dependa dessa ordem. O conjunto vazio é falso e {0} é verdadeiro — a regra de valor-verdade do Capítulo 11 aplicada a contêiner.

A unicidade usa igualdade e hash, então a armadilha do Capítulo 24 reaparece:

print({1, 1.0, True, "um"})
print(len({1, 1.0, True}))
{[1, 2]}
{1, 'um'}
1
TypeError: unhashable type: 'list'

Três formas de escrever o número um contam como um elemento. E lista não entra em conjunto, pelo mesmo motivo pelo qual não é chave.

25.2 As quatro operações

norte = {"onu-01", "onu-02", "onu-03"}
criticas = {"onu-02", "onu-05"}
print("uniao        |  ", sorted(norte | criticas))
print("intersecao   &  ", sorted(norte & criticas))
print("diferenca    -  ", sorted(norte - criticas))
print("dif. simet.  ^  ", sorted(norte ^ criticas))
uniao        |   ['onu-01', 'onu-02', 'onu-03', 'onu-05']
intersecao   &   ['onu-02']
diferenca    -   ['onu-01', 'onu-03']
dif. simet.  ^   ['onu-01', 'onu-03', 'onu-05']

O sorted está aí só para a saída ser estável na página — sem ele, a ordem varia.

A diferença entre operador e método não é estética:

print("so metodo aceita lista:", sorted(norte.union(["onu-09"])))
norte | ["onu-09"]
so metodo aceita lista: ['onu-01', 'onu-02', 'onu-03', 'onu-09']
TypeError: unsupported operand type(s) for |: 'set' and 'list'

Use o operador quando os dois lados já forem conjuntos (é mais legível) e o método quando o outro lado for uma lista ou um gerador (evita um set() a mais).

25.3 Comparar conjuntos

a = {1, 2}
b = {1, 2, 3}
print("a <= b subconjunto  :", a <= b, a.issubset(b))
print("a <  b proprio      :", a < b)
print("b >= a superconjunto:", b >= a)
print("disjuntos           :", a.isdisjoint({9}), a.isdisjoint(b))
print("iguais              :", {1, 2} == {2, 1})
print("nao comparaveis     :", {1, 9} <= {1, 2}, {1, 2} <= {1, 9})
a <= b subconjunto  : True True
a <  b proprio      : True
b >= a superconjunto: True
disjuntos           : True False
iguais              : True
nao comparaveis     : False False

A última linha é a que merece cuidado: <= entre conjuntos é ordem parcial, não total. {1, 9} não é subconjunto de {1, 2} e {1, 2} não é subconjunto de {1, 9} — os dois testes dão False sem que os conjuntos sejam iguais. Não dá para ordenar conjuntos com sorted esperando o comportamento de números.

25.4 Modificar

s = {"onu-01"}
s.add("onu-02")
s.add("onu-02")
print("add (idempotente):", sorted(s))
s.update(["onu-03", "onu-04"], {"onu-05"})
print("update           :", sorted(s))
s.discard("onu-99")
print("discard ausente  : sem erro")
s.remove("onu-99")
add (idempotente): ['onu-01', 'onu-02']
update           : ['onu-01', 'onu-02', 'onu-03', 'onu-04', 'onu-05']
discard ausente  : sem erro
remove ausente   : KeyError 'onu-99'

add de item existente não é erro nem duplica — é a idempotência que torna o conjunto tão conveniente para acumular. A diferença entre discard e remove é a mesma do .get e do [] no dicionário: um perdoa a ausência, o outro não.

pop() remove um item arbitrário (não há “primeiro”), e os operadores in-place |=, &=, -= e ^= existem todos.

25.5 frozenset

A versão imutável e, portanto, hashável:

chaveavel = frozenset({"onu-01", "onu-02"})
grupos = {frozenset({"onu-01", "onu-02"}): "placa 1", frozenset({"onu-03"}): "placa 2"}
print(grupos[frozenset({"onu-02", "onu-01"})])
print("conjunto de conjuntos:", {frozenset({1, 2}), frozenset({1, 2}), frozenset({3})})
{{1, 2}}
placa 1
conjunto de conjuntos: {frozenset({3}), frozenset({1, 2})}
TypeError: unhashable type: 'set'

Repare na consulta: a chave foi criada com os elementos em outra ordem e encontrou o mesmo grupo — conjunto não tem ordem, e o hash dele também não depende dela. É por isso que frozenset é a chave certa quando o identificador é “este conjunto de coisas”, independentemente da ordem em que foram escritas.

25.6 Deduplicar

O uso mais comum de conjunto é tirar repetidos, e a escolha tem uma consequência que costuma passar batida:

leituras = ["onu-03", "onu-01", "onu-03", "onu-02", "onu-01"]
print("set (perde ordem):     ", list(set(leituras)))
print("dict.fromkeys (mantem):", list(dict.fromkeys(leituras)))
set (perde ordem):      ['onu-03', 'onu-02', 'onu-01']
dict.fromkeys (mantem): ['onu-03', 'onu-01', 'onu-02']

A primeira linha muda de execução para execução; a segunda, nunca. dict.fromkeys preserva a ordem de primeira aparição porque o dicionário preserva ordem de inserção desde o Python 3.7 — é o mesmo fromkeys que causou o problema do Capítulo 24, aqui usado do jeito certo, com valor imutável e descartado.

A diferença de custo é grande:

import timeit

setup = 'itens = [f"onu-{i:05d}" for i in range(4000)] * 2'
a = timeit.timeit(
    """
vistos = []
for x in itens:
    if x not in vistos:
        vistos.append(x)
""",
    setup=setup,
    number=3,
)
b = timeit.timeit("list(dict.fromkeys(itens))", setup=setup, number=3)
c = timeit.timeit("set(itens)", setup=setup, number=3)
print(f"lista + in    {a * 1000:9.2f} ms")
print(f"dict.fromkeys {b * 1000:9.2f} ms")
print(f"set           {c * 1000:9.2f} ms")
print(f"razao lista/dict {a / b:6.0f}x")
lista + in       318.68 ms
dict.fromkeys      1.06 ms
set                0.66 ms
razao lista/dict    301x

O laço com in é quadrático: cada item novo é comparado com todos os anteriores. Com o dobro dos dados, ele fica quatro vezes mais lento, enquanto os outros dois só dobram.

25.7 Comparar dois estados

As views do Capítulo 24 se comportam como conjuntos, e é isso que torna a comparação de dois dicionários um exercício de uma linha por pergunta:

antes = {"onu-01": -19.5, "onu-02": -31.2, "onu-03": -26.4}
depois = {"onu-02": -31.2, "onu-03": -20.0, "onu-04": -8.0}
print("sumiram :", sorted(antes.keys() - depois.keys()))
print("novas   :", sorted(depois.keys() - antes.keys()))
print("comuns  :", sorted(antes.keys() & depois.keys()))
mudaram = {k for k in antes.keys() & depois.keys() if antes[k] != depois[k]}
print("mudaram :", sorted(mudaram))
print("inalterados:", sorted(antes.items() & depois.items()))
sumiram : ['onu-01']
novas   : ['onu-04']
comuns  : ['onu-02', 'onu-03']
mudaram : ['onu-03']
inalterados: [('onu-02', -31.2)]

A última linha usa items() como conjunto de pares — funciona porque os valores aqui são hasháveis. Com valores mutáveis (listas, dicionários), items() deixa de suportar operações de conjunto e é preciso comparar chave a chave.

A sintaxe {k for k in ... if ...} da penúltima linha é uma compreensão de conjunto, tema do próximo capítulo.

25.8 🐍 Jeito Pythônico

set() para o conjunto vazio. {} é dicionário, sempre.

Conjunto quando a pergunta é “pertence?” ou “é único?”. Se um in aparece dentro de um laço, a coleção do lado direito quase sempre deveria ser um conjunto.

# antipadrão
bloqueadas = ["onu-02", "onu-05"]
ativas = [o for o in leituras if o not in bloqueadas]
# pythônico
BLOQUEADAS = frozenset({"onu-02", "onu-05"})
ativas = [o for o in leituras if o not in BLOQUEADAS]

Constante de pertencimento é frozenset. Deixa claro que ninguém deve mexer, e é hashável de brinde.

Operações de conjunto no lugar de laços com if. cadastradas - responderam diz “silenciosas” numa expressão; o laço equivalente tem quatro linhas e uma chance de errar o sentido.

Não conte com a ordem. Nem a de inserção, nem a de execução anterior. Para saída estável, sorted(conjunto).

Para deduplicar preservando ordem, dict.fromkeys. set só quando a ordem não importa.

Cuidado ao mutar durante a iteração — vale a mesma regra do Capítulo 16: RuntimeError: Set changed size during iteration.

Sobre versões:

  • Python 3.0 — literal de conjunto {1, 2} e compreensão de conjunto passaram a existir (antes, só set([1, 2])).
  • Python 3.7 — dict.fromkeys virou o idioma oficial de deduplicação com ordem, quando a ordem do dicionário virou garantia.
  • Python 3.9 — as views de dicionário ganharam mapping, e os operadores de conjunto sobre elas continuam sendo a forma canônica de comparar dicionários.
  • Python 3.10 — set e frozenset como padrões no match funcionam por igualdade, não por estrutura: conjunto não é padrão de sequência.

13. O relatório de cobertura. Crie cobertura.py:

"""Comparacao de inventarios com operacoes de conjunto."""

CADASTRADAS = {
    "onu-01", "onu-02", "onu-03", "onu-04", "onu-05", "onu-06",
}
RESPONDERAM = {
    "onu-01", "onu-03", "onu-05", "onu-07",
}
EM_MANUTENCAO = frozenset({"onu-04", "onu-06"})


def relatorio(cadastradas, responderam, manutencao):
    """Devolve um dicionario com cada categoria da varredura."""
    silenciosas = cadastradas - responderam - manutencao
    return {
        "responderam": cadastradas & responderam,
        "silenciosas": silenciosas,
        "fantasmas": responderam - cadastradas,
        "em manutencao": cadastradas & manutencao,
        "divergencia": cadastradas ^ responderam,
    }


if __name__ == "__main__":
    r = relatorio(CADASTRADAS, RESPONDERAM, EM_MANUTENCAO)
    for rotulo, conjunto in r.items():
        print(f"{rotulo:<14} {len(conjunto):>2}  {sorted(conjunto)}")

    cobertura = len(r["responderam"]) / len(CADASTRADAS)
    print(f"\ncobertura: {cobertura:.0%}")
    print("tudo que respondeu esta cadastrado?", RESPONDERAM <= CADASTRADAS)
    print("manutencao e cadastro sao disjuntos?", EM_MANUTENCAO.isdisjoint(RESPONDERAM))

    urgentes = r["silenciosas"] | r["fantasmas"]
    print("exigem acao:", sorted(urgentes))
python cobertura.py
responderam     3  ['onu-01', 'onu-03', 'onu-05']
silenciosas     1  ['onu-02']
fantasmas       1  ['onu-07']
em manutencao   2  ['onu-04', 'onu-06']
divergencia     4  ['onu-02', 'onu-04', 'onu-06', 'onu-07']

cobertura: 50%
tudo que respondeu esta cadastrado? False
manutencao e cadastro sao disjuntos? True
exigem acao: ['onu-02', 'onu-07']

Cinco perguntas de negócio, cinco expressões de uma linha. A silenciosas encadeia duas diferenças — “está no cadastro, não respondeu e não está em manutenção” —, e a fantasmas é a pergunta inversa, que quase ninguém pensa em fazer com um laço: quem respondeu sem estar cadastrado. O False na penúltima linha é o alarme correspondente.

Repare também que EM_MANUTENCAO é frozenset e funcionou em todas as operações: para leitura, frozenset e set são intercambiáveis, e o frozenset documenta que aquela constante não muda.

25.10 Resumo

  • {} é dicionário vazio; conjunto vazio é set(). Com dois-pontos é dicionário, sem dois-pontos é conjunto.
  • Conjunto é a tabela hash do dicionário sem os valores: elementos únicos, hasháveis e sem ordem. A ordem de iteração de strings muda entre execuções, de propósito.
  • 1, 1.0 e True são o mesmo elemento; lista e conjunto não entram em conjunto, tuple e frozenset entram.
  • |, &, - e ^ exigem conjuntos dos dois lados; union, intersection, difference e symmetric_difference aceitam qualquer iterável.
  • <=, <, >= são ordem parcial: dois conjuntos podem não ser comparáveis, e os dois testes darem False.
  • add é idempotente; discard perdoa a ausência e remove levanta KeyError; pop tira um item arbitrário.
  • frozenset é imutável e hashável: serve de chave, de elemento de outro conjunto e de constante de pertencimento.
  • Deduplicar: set quando a ordem não importa, list(dict.fromkeys(x)) quando importa. O laço com in numa lista é quadrático — centenas de vezes mais lento já em alguns milhares de itens.
  • As views keys() e items() funcionam como conjuntos, o que transforma a comparação de dois dicionários em uma expressão por pergunta.
