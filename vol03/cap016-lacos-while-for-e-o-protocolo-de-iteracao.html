16  Laços: while, for e o protocolo de iteração

A rotina de limpeza do inventário tem uma linha de trabalho: tirar da lista as ONUs que estão fora do ar. O código tem quatro linhas e não parece ter onde errar.

onus = ["onu-01", "onu-02", "offline", "offline", "onu-05", "offline"]

for nome in onus:
    if nome == "offline":
        onus.remove(nome)

print(onus)
['onu-01', 'onu-02', 'onu-05', 'offline']

Sobrou uma. Nenhum erro, nenhum aviso, e a lista final está errada de um jeito que passa em qualquer revisão rápida — quem lê o código vê a intenção, não o resultado.

O motivo é que o for não percorre os elementos de uma lista: ele pede um item por vez a um iterador, e o iterador de lista trabalha com um índice interno que só sabe andar para frente. Cada remove encurta a lista sob os pés desse índice.

Dá para ver o índice andando se você desmontar o for na mão:

onus = ["onu-01", "onu-02", "offline", "offline", "onu-05", "offline"]
it = iter(onus)
i = 0
while True:
    try:
        nome = next(it)
    except StopIteration:
        break
    print(f"posicao {i}  o for ve {nome!r:<10} tamanho={len(onus)}")
    if nome == "offline":
        onus.remove(nome)
    i += 1
posicao 0  o for ve 'onu-01'   tamanho=6
posicao 1  o for ve 'onu-02'   tamanho=6
posicao 2  o for ve 'offline'  tamanho=6
posicao 3  o for ve 'onu-05'   tamanho=5
posicao 4  o for ve 'offline'  tamanho=5

Na posição 2 o laço encontra o primeiro "offline" e o remove. A lista encolhe, tudo desliza uma casa para a esquerda, o segundo "offline" passa a ocupar a posição 2 — e o índice interno já está indo para a 3. O elemento nunca é visto. O laço, que deveria dar seis voltas, deu cinco.

Este capítulo é sobre o mecanismo por trás disso: o que while e for realmente fazem, o que é um iterador, e por que quase todo laço escrito com índice em Python é um laço escrito errado.

16.1 while: repetir enquanto uma condição valer

O while é a repetição mais crua: testa uma condição e executa o bloco enquanto ela for verdadeira, com as mesmas regras de valor-verdade do Capítulo 15.

n = 0
saldo = 100.0
while saldo > 0:
    saldo -= 30.0
    n += 1
print(n, round(saldo, 2))
4 -20.0

Quatro voltas, e o saldo terminou negativo — a condição só é testada no começo de cada volta, nunca no meio. Se o bloco precisa parar no meio, isso é break, assunto do capítulo 17.

O uso natural do while é o caso em que você não sabe de antemão quantas iterações haverá: consumir uma fila, tentar de novo até dar certo, ler até o fim de um fluxo.

fila = ["job-1", "job-2", "job-3"]
while fila:
    tarefa = fila.pop(0)
    print("rodando", tarefa, "| restam", len(fila))
rodando job-1 | restam 2
rodando job-2 | restam 1
rodando job-3 | restam 0

Note o while fila: — a lista vazia é falsa, então a condição é o próprio esvaziamento. Escrever while len(fila) > 0: diria a mesma coisa com mais palavras.

O que não se faz em Python é usar while como contador:

# antipadrão: o for de C escrito em Python
i = 0
while i < len(linhas):
    processa(linhas[i])
    i += 1

Três oportunidades de errar (inicializar, comparar, incrementar) para fazer o que for linha in linhas: faz sem nenhuma. Todo laço que sabe quantas voltas vai dar é um for.

16.2 for: percorrer um iterável

O for do Python não é o for de C. Não existe contador, não existe condição de parada, não existe incremento. Existe um iterável e um alvo:

for nome, nivel in [("onu-01", -19.5), ("onu-03", -31.0)]:
    print(f"{nome}: {nivel:>7.1f}")
onu-01:   -19.5
onu-03:   -31.0

O alvo pode ser um desempacotamento, como acima. E o iterável pode ser qualquer coisa que saiba produzir itens: lista, tupla, string, dicionário, arquivo aberto, range, um objeto seu.

d = {"a": 1, "b": 2}
for chave in d:
    print(chave, end=" ")
print()
for chave, valor in d.items():
    print(chave, valor, end="  ")
print()
a b
a 1  b 2

Iterar um dicionário direto dá as chaves; .items() dá os pares e .values() dá os valores. Errar isso é o TypeError: cannot unpack non-sequence mais comum de quem vem de outra linguagem.

16.3 O protocolo de iteração

Por baixo, o for faz exatamente três coisas: chama iter() no objeto, chama next() repetidamente no resultado, e para quando aparece StopIteration.

it = iter(["a", "b", "c"])
print(it)
print(next(it))
print(next(it))
print(next(it))
try:
    next(it)
except StopIteration:
    print("StopIteration")
<list_iterator object at 0x7a01b33df0a0>
a
b
c
StopIteration

O endereço muda a cada execução; o resto não. E é assim que o for é implementado — o código abaixo é o for escrito à mão:

seq = ["a", "b"]
it = iter(seq)
while True:
    try:
        item = next(it)
    except StopIteration:
        break
    print("processando", item)
processando a
processando b

A distinção entre iterável e iterador é a que resolve metade das confusões:

  • Um iterável sabe produzir um iterador (__iter__). Lista, tupla, string, dicionário e range são iteráveis, e cada for sobre eles começa do zero.
  • Um iterador sabe produzir o próximo item (__next__), guarda a posição e se esgota. Todo iterador também é iterável — iter(it) is it —, o que é o truque que permite passar um iterador direto para um for.
nums = [1, 2, 3]
it = iter(nums)
print(list(it))
print(list(it))
print(iter(it) is it)
[1, 2, 3]
[]
True

A segunda chamada devolve lista vazia. Isso morde de verdade quando o iterador vem de longe: zip, enumerate, map, filter, reversed e o objeto de arquivo aberto são iteradores, não sequências, e consumir duas vezes devolve nada na segunda. Quando você precisa passar mais de uma vez, materialize com list() antes.

Cada tipo tem o seu iterador:

print(type(iter("abc")), type(iter({"a": 1})), type(iter((1, 2))))
print(type(iter(range(3))))
<class 'str_ascii_iterator'> <class 'dict_keyiterator'> <class 'tuple_iterator'>
<class 'range_iterator'>

16.3.1 Um iterável seu

Implementar o protocolo é implementar dois métodos. O padrão correto separa o iterável (que pode ser percorrido muitas vezes) do iterador (que se esgota):

class Rampa:
    def __init__(self, inicio, fim):
        self.inicio = inicio
        self.fim = fim

    def __iter__(self):
        return RampaIterador(self.inicio, self.fim)


class RampaIterador:
    def __init__(self, atual, fim):
        self.atual = atual
        self.fim = fim

    def __iter__(self):
        return self

    def __next__(self):
        if self.atual > self.fim:
            raise StopIteration
        valor = self.atual
        self.atual += 1
        return valor


r = Rampa(1, 4)
print(list(r))
print(list(r))
print(sum(r), max(r))
[1, 2, 3, 4]
[1, 2, 3, 4]
10 4

Duas listas iguais: cada list(r) pediu um iterador novo. E, de graça, o objeto passou a funcionar com sum, max, sorted, in e desempacotamento — tudo que consome iterável passa a aceitar Rampa. Se __iter__ devolvesse self, a segunda linha sairia vazia e o sum veria uma rampa gasta.

Na prática você quase nunca escreve essas duas classes: um gerador com yield faz o mesmo em quatro linhas, e é assunto do Volume 8. Mas é este o protocolo que o gerador implementa por baixo.

16.4 range não é uma lista

r = range(0, 10, 3)
print(r, list(r), len(r), r[2], 9 in r, 4 in r)
range(0, 10, 3) [0, 3, 6, 9] 4 6 True False

range é uma sequência preguiçosa: guarda início, fim e passo, e calcula cada valor na hora. Tem comprimento, aceita índice e responde in — e o in é calculado por aritmética, não por varredura.

import sys

print(sys.getsizeof(range(1_000_000)), sys.getsizeof(list(range(1_000_000))))
48 8000056

Quarenta e oito bytes contra oito megabytes. range é o motivo de nunca precisar materializar uma sequência de índices.

O que não se faz com ele é isto:

# antipadrão: índice só para poder indexar
for i in range(len(linhas)):
    print(i, linhas[i])
# pythônico
for i, valor in enumerate(linhas, start=1):
    print(i, valor)
1 -19.5
2 -31.0
3 -8.0

enumerate produz pares (índice, valor) e aceita start, o que resolve de uma vez a numeração começando em 1 para relatório. range(len(...)) só se justifica quando você realmente precisa do índice para outra coisa — escrever numa posição, por exemplo.

16.5 zip: percorrer em paralelo

nomes = ["onu-01", "onu-02", "onu-03"]
niveis = [-19.5, -31.0]
print(list(zip(nomes, niveis)))
[('onu-01', -19.5), ('onu-02', -31.0)]

zip para no mais curto, em silêncio. A terceira ONU sumiu do relatório e ninguém foi avisado. Desde o Python 3.10 existe a proteção:

try:
    print(list(zip(nomes, niveis, strict=True)))
except ValueError as e:
    print("ValueError:", e)
ValueError: zip() argument 2 is shorter than argument 1

Sempre que as sequências deveriam ter o mesmo tamanho, strict=True transforma um bug silencioso em uma exceção. Quando o truncamento é intencional, deixe sem — e escreva no comentário que é intencional.

16.6 Mudar o que se está percorrendo

De volta ao problema da abertura. A regra geral é: não modifique um contêiner enquanto itera sobre ele. Em lista, o resultado é silencioso e errado; em dicionário e conjunto, o Python detecta e falha alto:

estoque = {"onu-01": 3, "onu-02": 0, "onu-03": 5}
try:
    for chave, qtd in estoque.items():
        if qtd == 0:
            del estoque[chave]
except RuntimeError as e:
    print("RuntimeError:", e)
RuntimeError: dictionary changed size during iteration

Há três saídas corretas, em ordem de preferência:

onus = ["onu-01", "onu-02", "offline", "offline", "onu-05", "offline"]

# 1. construir uma lista nova (o normal)
ativas = [n for n in onus if n != "offline"]

# 2. substituir o conteúdo no lugar, quando outras referências apontam para a lista
onus[:] = [n for n in onus if n != "offline"]

print(ativas)
print(onus)
['onu-01', 'onu-02', 'onu-05']
['onu-01', 'onu-02', 'onu-05']

A primeira é a resposta padrão: filtrar é produzir uma coleção nova, não mutilar a antiga. A segunda usa a atribuição a fatia do Capítulo 12 para trocar o conteúdo mantendo o mesmo objeto — importa quando outra parte do programa guarda uma referência a essa lista, pela mecânica do Capítulo 8. A terceira é iterar sobre uma cópia, que é o que salva o dicionário:

estoque = {"onu-01": 3, "onu-02": 0, "onu-03": 5}
for chave in list(estoque):
    if estoque[chave] == 0:
        del estoque[chave]
print(estoque)
{'onu-01': 3, 'onu-03': 5}

list(estoque) congela as chaves antes do laço começar; o que muda é o dicionário, não a lista que está sendo percorrida.

A sintaxe [n for n in onus if ...] é uma compreensão de lista, assunto do Volume 4. Ela aparece aqui porque é a resposta idiomática ao problema deste capítulo, e vale ler por enquanto como “um for que produz uma lista”.

16.7 Laços aninhados

matriz = [[1, 2, 3], [4, 5, 6]]
for linha in matriz:
    for valor in linha:
        print(valor, end=" ")
    print()
1 2 3
4 5 6

Funciona e é legível em dois níveis. A partir do terceiro, e sempre que os dois laços percorrem coleções independentes, itertools.product diz o mesmo em uma linha — e o custo continua sendo o produto dos tamanhos. Dois laços de mil itens são um milhão de voltas, o que é a origem da maioria dos “ficou lento quando os dados cresceram”.

16.8 🐍 Jeito Pythônico

Itere sobre o objeto, não sobre índices. for item in colecao: é o padrão; for i, item in enumerate(colecao): quando o índice também é necessário; range(len(...)) praticamente nunca.

# antipadrão
for i in range(len(nomes)):
    print(nomes[i], niveis[i])
# pythônico
for nome, nivel in zip(nomes, niveis, strict=True):
    print(nome, nivel)

while para o que não tem contagem conhecida; for para todo o resto. while com contador manual é for escrito com três chances a mais de errar.

Nunca modifique a coleção que está sendo percorrida. Construa uma nova, ou itere sobre uma cópia (list(d)), ou atribua à fatia (lst[:] = ...).

zip(..., strict=True) sempre que os tamanhos deveriam bater (3.10+). O truncamento silencioso é a categoria de bug mais barata de evitar e mais cara de achar.

Cuidado com iteradores consumidos. zip, enumerate, map, filter, reversed e arquivos abertos são de uma passada só. Se vai usar duas vezes, list() antes.

for _ in range(n) quando o valor não importa. O sublinhado é a convenção para “variável que existe só porque a sintaxe exige”.

Não conte na mão o que a biblioteca já conta. sum, min, max, any, all, sorted e collections.Counter substituem laços de acumulação inteiros, e cada um deles roda em C.

# antipadrão
total = 0
for n in niveis:
    total += n
media = total / len(niveis)
# pythônico
media = sum(niveis) / len(niveis)

Iterável reutilizável, iterador descartável. Ao escrever uma classe iterável, __iter__ devolve um objeto novo; só um iterador devolve self.

Sobre versões:

  • Python 3.0 — range, zip e map passaram a ser preguiçosos; no Python 2 devolviam listas.
  • Python 3.6 — o dicionário passou a preservar a ordem de inserção (detalhe de implementação no 3.6, garantia da linguagem no 3.7), então a ordem de iteração de um dict é previsível.
  • Python 3.10 — zip(..., strict=True) (PEP 618).
  • Python 3.12 — laços mais rápidos por conta da especialização adaptativa do interpretador (PEP 659), sem mudança de sintaxe.

11. Escreva um iterável próprio. Crie janela.py:

"""Media movel sobre uma sequencia de leituras, como iteravel proprio."""


class JanelaMovel:
    """Iteravel (reutilizavel) que produz a media de cada janela de tamanho n."""

    def __init__(self, dados, tamanho):
        if tamanho < 1:
            raise ValueError("tamanho da janela precisa ser >= 1")
        self.dados = list(dados)
        self.tamanho = tamanho

    def __iter__(self):
        return _JanelaIterador(self.dados, self.tamanho)


class _JanelaIterador:
    def __init__(self, dados, tamanho):
        self.dados = dados
        self.tamanho = tamanho
        self.pos = 0

    def __iter__(self):
        return self

    def __next__(self):
        fim = self.pos + self.tamanho
        if fim > len(self.dados):
            raise StopIteration
        fatia = self.dados[self.pos:fim]
        self.pos += 1
        return sum(fatia) / self.tamanho


if __name__ == "__main__":
    leituras = [-19.5, -19.8, -21.2, -25.9, -27.1, -31.0]
    janela = JanelaMovel(leituras, 3)

    for i, media in enumerate(janela, start=1):
        print(f"janela {i}: {media:>7.2f} dBm")

    print("de novo (o iteravel e reutilizavel):", [round(m, 2) for m in janela])
    print("pior media:", round(min(janela), 2))

    it = iter(janela)
    print("primeiro next():", round(next(it), 2))
    print("resto:", [round(m, 2) for m in it])
    print("esgotado:", list(it))

12. Use o iterável em algo real. Crie tendencia.py:

"""Detecta ONUs em degradacao comparando cada leitura com a anterior."""

from janela import JanelaMovel

HISTORICO = {
    "onu-01": [-19.5, -19.6, -19.4, -19.5],
    "onu-03": [-24.0, -26.1, -28.7, -31.0],
    "onu-04": [-27.0, -26.2, -25.1, -24.4],
}

for onu, leituras in HISTORICO.items():
    quedas = 0
    for anterior, atual in zip(leituras, leituras[1:]):
        if atual < anterior:
            quedas += 1
    media = sum(JanelaMovel(leituras, 2)) / (len(leituras) - 1)
    veredito = "degradando" if quedas >= 3 else "estavel"
    print(f"{onu}  quedas={quedas}/{len(leituras) - 1}  media={media:>7.2f}  {veredito}")

O zip(leituras, leituras[1:]) é o idioma para percorrer pares consecutivos: a mesma sequência contra ela mesma deslocada de um. Nenhum índice, nenhum range(len(...)), e o zip para sozinho no penúltimo elemento.

16.10 Resumo

  • while repete enquanto a condição for verdadeira e testa só no início da volta; é a escolha certa quando o número de iterações não é conhecido. while com contador manual é um for mal escrito.
  • for percorre um iterável: chama iter() uma vez, next() a cada volta, e encerra ao capturar StopIteration.
  • Iterável produz um iterador novo a cada iter(); iterador guarda a posição, devolve self em __iter__ e se esgota. zip, enumerate, map, filter e arquivos abertos são iteradores de uma passada só.
  • Implementar __iter__ e __next__ faz o objeto funcionar com for, sum, min, sorted, in e desempacotamento de uma vez.
  • range é sequência preguiçosa: 48 bytes para um milhão de valores, com índice, len e in por aritmética.
  • enumerate no lugar de range(len(...)); zip para percorrer em paralelo, com strict=True (3.10+) sempre que os tamanhos deveriam bater.
  • Modificar a coleção durante a iteração pula elementos em lista (silenciosamente) e levanta RuntimeError em dicionário e conjunto. Construa uma coleção nova, itere sobre list(d) ou atribua a lst[:].
  • zip(seq, seq[1:]) percorre pares consecutivos; sum, max, any e all substituem laços de acumulação inteiros.
