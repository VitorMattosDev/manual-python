18  Definindo funções: parâmetros, argumentos e retorno

O script de relatório cresceu, e alguém fez a coisa certa: extraiu o cálculo da média para uma função.

def media_dbm(leituras):
    if leituras:
        total = sum(leituras)
        media = total / len(leituras)
        print(f"media calculada: {media:.2f}")


resultado = media_dbm([-19.5, -21.3, -20.2])
print("resultado:", resultado)
print("resultado + 3 =", resultado + 3)
media calculada: -20.33
resultado: None
Traceback (most recent call last):
  File "/home/vitor/lab18/media_ruim.py", line 10, in <module>
    print("resultado + 3 =", resultado + 3)
                             ~~~~~~~~~~^~~
TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'

A média foi calculada, apareceu na tela, e mesmo assim resultado é None. A função imprimiu o valor em vez de devolver o valor — e uma função sem return devolve None, sempre, sem avisar.

O detalhe cruel é a primeira linha da saída: o número certo apareceu. Quem testou no terminal viu -20.33 e deu por encerrado. O erro só aparece quando alguém tenta usar o resultado, possivelmente num arquivo diferente, dias depois — e o NoneType do traceback não diz nada sobre a função que faltou devolver.

def media(leituras):
    if not leituras:
        return None
    return sum(leituras) / len(leituras)


print(media([-19.5, -21.3, -20.2]))
print(media([]))
-20.333333333333332
None

Agora o None é uma decisão escrita, não um acidente. Este capítulo é sobre o que acontece quando você escreve def: o objeto que nasce, o quadro que a chamada empilha, como os argumentos chegam nos parâmetros e o que exatamente volta.

18.1 Anatomia de uma definição

def classificar(nivel):
    """Devolve a faixa operacional de um nivel optico em dBm."""
    if nivel < -28:
        return "critico"
    if nivel < -25:
        return "atencao"
    return "normal"

Duas coisas que essa figura resume e que valem repetir:

O def cria um objeto. Não é declaração, é instrução executável — ela roda, constrói um objeto do tipo function e o liga a um nome, do mesmo jeito que uma atribuição comum liga um nome a uma lista.

def classificar(nivel):
    """Devolve a faixa operacional de um nivel optico em dBm."""
    ...


print(type(classificar), classificar.__name__)
print(classificar.__doc__)
apelido = classificar
print(apelido(-31.0), apelido is classificar)
<class 'function'> classificar
Devolve a faixa operacional de um nivel optico em dBm.
critico True

apelido e classificar são dois nomes para o mesmo objeto, exatamente como no Capítulo 8. O que isso destrava — passar função como argumento, guardar em dicionário, devolver de outra função — é o assunto do Capítulo 21.

O corpo só roda na chamada. Um def com erro de digitação lá dentro é aceito sem reclamar; o NameError aparece na primeira chamada, que pode ser em produção.

18.2 Parâmetro e argumento

A distinção é chata e útil:

  • Parâmetro é o nome na definição (nivel).
  • Argumento é o valor na chamada (-31.0).

Argumentos podem ser passados por posição ou por nome:

def area(base, altura):
    return base * altura / 2


print(area(3, 4))
print(area(altura=4, base=3))
6.0
6.0

Passar por nome documenta a chamada e imuniza contra troca de ordem. As regras completas — valores padrão, *args, **kwargs, parâmetros só-posicionais — são o Capítulo 19.

18.3 return

return faz duas coisas ao mesmo tempo: encerra a função e devolve um valor. É por isso que a cláusula de guarda do Capítulo 15 funciona tão bem dentro de função.

Sem valor, return devolve None; sem return nenhum, também:

def registrar(nivel):
    if nivel < -28:
        return "critico"
    print("nao critico")
    return


print(registrar(-31.0))
print(registrar(-19.5))
critico
nao critico
None

Um return nu é uma saída antecipada legítima. O que não é legítimo é a função às vezes devolver e às vezes não — o caso da abertura. Se um caminho devolve str, todos devem devolver str ou None de propósito, e o None precisa estar escrito.

18.3.1 “Vários valores” é uma tupla

Python não devolve múltiplos valores; devolve um objeto, que costuma ser uma tupla:

def estatisticas(leituras):
    return min(leituras), max(leituras), sum(leituras) / len(leituras)


r = estatisticas([-19.5, -31.0, -20.2])
print(r, type(r))
pior, melhor, med = estatisticas([-19.5, -31.0, -20.2])
print(f"{pior=} {melhor=} {med=:.2f}")
(-31.0, -19.5, -23.566666666666666) <class 'tuple'>
pior=-31.0 melhor=-19.5 med=-23.57

As vírgulas do return montam a tupla; o desempacotamento do lado esquerdo a desmonta. A partir de três ou quatro valores, uma tupla posicional vira armadilha (quem lembra a ordem?), e a resposta é NamedTuple ou dataclass, do Volume 7.

E a sintaxe f"{pior=}", do Capítulo 13, é o depurador de pobre que todo mundo usa: imprime o nome e o valor juntos.

18.4 O que a chamada faz

Chamar uma função empilha um quadro (frame): um espaço novo onde os parâmetros já nascem ligados aos argumentos e onde vivem as variáveis locais. Quando a função retorna, o quadro é desempilhado.

É a pilha que o traceback do Capítulo 7 imprime:

TABELA = {"onu-01": -19.5, "onu-02": -31.2}


def nivel_de(onu):
    return TABELA[onu]


def relatar(onu):
    return f"{onu}: {nivel_de(onu)} dBm"


print(relatar("onu-01"))
print(relatar("onu-99"))
onu-01: -19.5 dBm
Traceback (most recent call last):
  File "/home/vitor/lab18/consulta.py", line 13, in <module>
    print(relatar("onu-99"))
          ~~~~~~~^^^^^^^^^^
  File "/home/vitor/lab18/consulta.py", line 9, in relatar
    return f"{onu}: {nivel_de(onu)} dBm"
                     ~~~~~~~~^^^^^
  File "/home/vitor/lab18/consulta.py", line 5, in nivel_de
    return TABELA[onu]
           ~~~~~~^^^^^
KeyError: 'onu-99'

18.5 Como os argumentos chegam

Python não é “por valor” nem “por referência”: o que acontece é que o parâmetro vira mais um nome para o objeto que veio de fora, exatamente como uma atribuição. As consequências são duas, e é preciso as duas para não se enganar.

Mutar o objeto afeta quem chamou:

def anexar(destino, item):
    destino.append(item)


lista = ["a"]
anexar(lista, "b")
print("depois de anexar: ", lista)
depois de anexar:  ['a', 'b']

Reatribuir o parâmetro não afeta ninguém:

def rebatizar(destino):
    destino = ["novo"]
    return destino


volta = rebatizar(lista)
print("depois de rebatizar:", lista, "| devolvido:", volta)
depois de rebatizar: ['a', 'b'] | devolvido: ['novo']

A atribuição dentro da função só reapontou o nome local. Dá para ver com id:

def inspeciona(obj):
    print("dentro:               ", id(obj))
    obj = "outro"
    print("depois da atribuicao: ", id(obj))


texto = "original"
print("fora, antes:          ", id(texto))
inspeciona(texto)
print("fora, depois:         ", id(texto), texto)
fora, antes:           124197974277104
dentro:                124197974277104
depois da atribuicao:  124197974127408
fora, depois:          124197974277104 original

Os identificadores mudam a cada execução; o padrão não muda. Entrou com o mesmo id (é o mesmo objeto), a atribuição criou outro id só lá dentro, e o de fora ficou igual.

Daí a regra prática: uma função ou devolve um valor novo, ou modifica o que recebeu — não as duas coisas, e o nome deve dizer qual das duas. Modificar o argumento sem avisar é a origem de bugs que atravessam módulos.

18.6 Docstring

A docstring é a primeira instrução do corpo, entre aspas triplas, e é o que help() mostra:

help(classificar)
Help on function classificar in module __main__:

classificar(nivel)
    Devolve a faixa operacional de um nivel optico em dBm.

A PEP 257 pede uma linha imperativa curta (“Devolve…”, “Calcula…”, “Grava…”), e, se precisar de mais, uma linha em branco e o resto. Comentário # explica como; docstring explica o que e para quem chama.

18.7 Anotações de tipo

def normaliza(nome: str, casas: int) -> str:
    return nome.strip().lower()[:casas]


print(normaliza("  ONU-Norte-01  ", 8))
print(normaliza.__annotations__)
print(normaliza(123, 2))
onu-nort
{'nome': <class 'str'>, 'casas': <class 'int'>, 'return': <class 'str'>}
Traceback (most recent call last):
  File "/home/vitor/lab18/anotacao.py", line 7, in <module>
    print(normaliza(123, 2))
          ~~~~~~~~~^^^^^^^^
  File "/home/vitor/lab18/anotacao.py", line 2, in normaliza
    return nome.strip().lower()[:casas]
           ^^^^^^^^^^
AttributeError: 'int' object has no attribute 'strip'

A anotação dizia str e o 123 passou sem reclamação: o interpretador não verifica anotações em tempo de execução. Elas ficam guardadas em __annotations__ e servem para o verificador estático (mypy, pyright), para o editor e para quem lê. O erro veio depois, de dentro, quando o int não soube fazer .strip(). Tipagem é o Volume 11; aqui basta a regra: anotar é documentar de forma verificável, não é validar.

18.8 Funções que devolvem None de propósito

Parte da biblioteca padrão devolve None deliberadamente, para deixar claro que a operação foi no lugar:

onus = ["onu-03", "onu-01", "onu-02"]
devolvido = onus.sort()
print("sort devolveu:", devolvido)
print("lista agora:  ", onus)

outras = ["onu-03", "onu-01", "onu-02"]
print("sorted devolveu:", sorted(outras), "| original:", outras)
sort devolveu: None
lista agora:   ['onu-01', 'onu-02', 'onu-03']
sorted devolveu: ['onu-01', 'onu-02', 'onu-03'] | original: ['onu-03', 'onu-01', 'onu-02']

onus = onus.sort() é o erro clássico: a lista ordenada é jogada fora e onus vira None. A convenção vale também para list.append, dict.update e random.shuffle — e vale para o seu código: se a função muda o argumento, não devolva ele também, porque isso convida a encadear chamadas que parecem funcionais e não são.

18.9 Recursão, em uma seção curta

Uma função pode chamar a si mesma. Precisa de um caso base, e o Python limita a profundidade:

import sys


def profundidade(n):
    return profundidade(n + 1)


def fatorial(n):
    """Fatorial de n, com caso base explicito."""
    if n <= 1:
        return 1
    return n * fatorial(n - 1)


print("limite:", sys.getrecursionlimit())
print("fatorial(20):", fatorial(20))
try:
    profundidade(0)
except RecursionError as e:
    print("RecursionError:", e)
limite: 1000
fatorial(20): 2432902008176640000
RecursionError: maximum recursion depth exceeded

Mil quadros e acabou. O Python não faz otimização de chamada de cauda, e a decisão é deliberada: Guido van Rossum argumentou que ela destruiria os tracebacks, que são mais valiosos. Em Python, recursão é ferramenta para estrutura recursiva (árvore, JSON aninhado, sistema de arquivos), não substituto de laço.

18.10 🐍 Jeito Pythônico

Uma função, uma responsabilidade, um nome de verbo. carregar, classificar, formatar, resumir. Se o nome precisa de “e” (carrega_e_valida), são duas funções.

Calcular e imprimir são trabalhos diferentes. A função devolve; quem chamou decide se imprime, grava ou soma. Foi essa mistura que produziu o bug da abertura, e ela também impede testar a função sem capturar a saída padrão.

Torne o None explícito. Se a função pode não ter resposta, escreva return None no caminho correspondente. None implícito é indistinguível de esquecimento.

Não misture cálculo com mutação. Ou devolve valor novo (sorted), ou muda no lugar e devolve None (sort).

Docstring em toda função pública, na forma imperativa, dizendo o que devolve.

Anote os tipos quando a assinatura não for óbvia. Custa pouco, o editor usa na hora, e o mypy transforma em verificação de verdade.

# antipadrão: imprime, não devolve, e o nome não diz o que faz
def dados(x):
    print(sum(x) / len(x))
# pythônico
def media(leituras: list[float]) -> float:
    """Devolve a media aritmetica das leituras."""
    return sum(leituras) / len(leituras)

Prefira list[float] a typing.List[float]. A forma nova vale desde o Python 3.9 (PEP 585); a antiga só sobrevive em código legado.

Cuidado com o argumento mutável que você não pediu. Se a função guarda o que recebeu (numa lista de estado, num atributo), guarde uma cópia — senão quem chamou pode mudar por baixo depois.

Sobre versões:

  • Python 3.0 — anotações de função (PEP 3107), sem semântica definida.
  • Python 3.5 — módulo typing e o significado padrão das anotações (PEP 484).
  • Python 3.8 — parâmetros só-posicionais com / (PEP 570), assunto do Capítulo 19.
  • Python 3.9 — list[float] e dict[str, int] direto nos tipos embutidos (PEP 585).
  • Python 3.10 — X | Y no lugar de Union[X, Y] (PEP 604).
  • Python 3.12 — sintaxe nova de genéricos, def f[T](x: T) -> T: (PEP 695).
  • Python 3.14 — anotações passam a ser avaliadas de forma preguiçosa (PEP 649), o que muda o comportamento de __annotations__ em referências adiante. Na 3.13, from __future__ import annotations é o jeito de antecipar isso.

"""Relatorio de niveis opticos, escrito como funcoes pequenas e testaveis."""

import csv
from pathlib import Path

CRITICO = -28.0
ATENCAO = -25.0
SATURACAO = -8.0


def carregar(caminho):
    """Le o CSV e devolve uma lista de pares (onu, nivel ou None)."""
    texto = Path(caminho).read_text(encoding="utf-8")
    linhas = csv.DictReader(texto.splitlines(), delimiter=";")
    return [
        (l["onu"], float(l["nivel"]) if l["nivel"].strip() else None) for l in linhas
    ]


def classificar(nivel):
    """Faixa operacional de um nivel em dBm; None quando nao ha leitura."""
    if nivel is None:
        return "sem leitura"
    if nivel < CRITICO:
        return "critico"
    if nivel < ATENCAO:
        return "atencao"
    if nivel <= SATURACAO:
        return "normal"
    return "saturado"


def resumir(registros):
    """Devolve (total, quantidade de problemas, pior leitura registrada)."""
    medidos = [n for _, n in registros if n is not None]
    problemas = sum(1 for _, n in registros if classificar(n) != "normal")
    return len(registros), problemas, min(medidos)


def formatar(onu, nivel):
    """Uma linha de relatorio, ja alinhada."""
    medida = "  ---  " if nivel is None else f"{nivel:>7.1f}"
    return f"{onu}  {medida}  {classificar(nivel)}"


def main(caminho="leituras.csv"):
    registros = carregar(caminho)
    for onu, nivel in registros:
        print(formatar(onu, nivel))
    total, problemas, pior = resumir(registros)
    print("-" * 34)
    print(f"{total} ONUs, {problemas} com problema, pior leitura {pior} dBm")


if __name__ == "__main__":
    main()

Nenhuma dessas quatro chamadas leu arquivo, imprimiu relatório ou dependeu do resto do programa. Uma função que só devolve é uma função que se testa em uma linha — e é por isso que “devolva, não imprima” é a regra que mais rende neste capítulo. O if __name__ == "__main__": que protege o main() é o que permite importar sem executar; a mecânica dele é o Capítulo 15 aplicada a uma variável do módulo, e o assunto completo é o Volume 5.

18.12 Resumo

  • def é instrução executável: cria um objeto function e liga a um nome. O corpo só roda na chamada, então erro dentro dele aparece tarde.
  • Função sem return devolve None, e função que imprime não é função que devolve — a confusão entre as duas é o bug de abertura deste capítulo.
  • return encerra e devolve ao mesmo tempo; devolver “vários valores” é devolver uma tupla, desmontada por desempacotamento.
  • Parâmetro é o nome na definição; argumento é o valor na chamada, passado por posição ou por nome.
  • Cada chamada empilha um quadro com os parâmetros ligados aos argumentos; a pilha é exatamente o que o traceback imprime, da base para o topo.
  • O parâmetro é mais um nome para o objeto recebido: mutar afeta quem chamou, reatribuir não afeta ninguém.
  • Uma função ou devolve valor novo (sorted) ou muda no lugar e devolve None (sort) — nunca as duas.
  • Docstring diz o que a função faz e alimenta o help(); anotações documentam tipos e não são verificadas em execução.
  • Recursão precisa de caso base e esbarra em sys.getrecursionlimit() (1000 por padrão); o Python não otimiza chamada de cauda, por decisão de projeto.
