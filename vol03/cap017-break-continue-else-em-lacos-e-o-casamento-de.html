17  break, continue, else em laços e o casamento de padrões

O inventário da rede é um dicionário de OLTs, cada uma com as suas ONUs. A função procura a primeira ONU com nível crítico:

REDE = {
    "olt-norte": {"onu-01": -19.5, "onu-02": -31.2, "onu-03": -20.1},
    "olt-sul": {"onu-04": -18.0, "onu-05": -29.8},
    "olt-leste": {"onu-06": -21.4},
}


def primeira_critica(rede):
    achada = None
    for olt, onus in rede.items():
        for onu, nivel in onus.items():
            if nivel < -28:
                achada = (olt, onu, nivel)
                break
    return achada


print(primeira_critica(REDE))
('olt-sul', 'onu-05', -29.8)

A primeira crítica é a onu-02, com −31,2 dBm, na olt-norte. A função devolveu a onu-05, com −29,8 — que é a última, e a menos grave das duas. O chamado foi aberto para o cliente errado.

O break fez exatamente o que ele faz: saiu do laço mais interno. O laço externo continuou percorrendo as outras OLTs, encontrou outra crítica e sobrescreveu achada. Em Python não existe break com rótulo, então o break de dentro nunca sai de dois níveis.

A correção mais limpa não é um break melhor — é não precisar de break:

def primeira_critica(rede):
    for olt, onus in rede.items():
        for onu, nivel in onus.items():
            if nivel < -28:
                return olt, onu, nivel
    return None


print(primeira_critica(REDE))
('olt-norte', 'onu-02', -31.2)

return sai de todos os laços de uma vez, porque sai da função inteira. É por isso que “extraia a busca para uma função” é a resposta padrão para break aninhado.

Este capítulo trata das três instruções que alteram o curso de um laço — break, continue e a cláusula else que quase ninguém conhece — e do match, que desde o Python 3.10 substitui escadas inteiras de condicionais quando a decisão é sobre a forma do dado.

17.1 break: abandonar o laço

break encerra o laço imediatamente, sem terminar a volta atual e sem avaliar a condição de novo. Vale para for e para while, e afeta um nível.

Quando o break aninhado não pode virar função, a saída é uma bandeira explícita:

achada = None
for olt, onus in REDE.items():
    for onu, nivel in onus.items():
        if nivel < -28:
            achada = (olt, onu, nivel)
            break
    if achada is not None:
        break
print(achada)
('olt-norte', 'onu-02', -31.2)

Funciona, e é feio: dois break e um teste extra para fazer o trabalho de um return. Prefira a função.

17.2 continue: pular para a próxima volta

continue abandona o resto do bloco e vai direto para a próxima iteração — no while, isso significa reavaliar a condição; no for, pedir o próximo item.

O uso que se paga é o de filtro na entrada, que é a cláusula de guarda do Capítulo 15 aplicada a laço:

soma, lidos, descartados = 0.0, 0, 0
for linha in linhas:
    if not linha.strip():
        descartados += 1
        continue
    if linha.startswith("#"):
        descartados += 1
        continue
    try:
        valor = float(linha)
    except ValueError:
        descartados += 1
        continue
    soma += valor
    lidos += 1

Cada caso ruim é tratado e descartado na hora, e o corpo útil do laço fica no fim, sem indentação nenhuma. A alternativa com if aninhado empurraria as duas últimas linhas para quatro níveis de profundidade.

Um cuidado no while: um continue que pula o incremento é laço infinito.

# antipadrão: se a linha for vazia, i nunca cresce
i = 0
while i < len(linhas):
    if not linhas[i]:
        continue
    processa(linhas[i])
    i += 1

É mais um argumento para não usar while com contador.

17.3 else em laço: “terminou sem break”

Esta é a construção mais mal-batizada do Python. O else de um laço executa quando o laço termina naturalmente — sem break. Se tivesse sido chamado nobreak, ninguém teria dificuldade.

for i in range(3):
    print(i, end=" ")
else:
    print("| else rodou")

for i in range(3):
    if i == 1:
        break
    print(i, end=" ")
else:
    print("| else rodou")
print("| else nao rodou")
0 1 2 | else rodou
0 | else nao rodou

O par break/else existe para um caso específico: a busca que precisa distinguir “achei” de “varri tudo e não achei”, sem bandeira nenhuma.

alvo = "onu-99"
for onu in REDE["olt-norte"]:
    if onu == alvo:
        print("encontrada")
        break
else:
    print(f"{alvo} nao esta na olt-norte")
onu-99 nao esta na olt-norte

O exemplo canônico é o teste de primalidade, onde o else significa “nenhum divisor foi encontrado”:

for n in (91, 97, 2):
    for divisor in range(2, int(n**0.5) + 1):
        if n % divisor == 0:
            print(f"{n} = {divisor} x {n // divisor}")
            break
    else:
        print(f"{n} e primo")
91 = 7 x 13
97 e primo
2 e primo

O caso do 2 mostra o comportamento com laço que não dá volta nenhuma: range(2, 2) é vazio, o for termina sem break, e o else roda. Laço vazio conta como “terminou sem break” — é o detalhe que mais surpreende.

O while tem a mesma cláusula, com o mesmo significado:

tentativas = 0
while tentativas < 3:
    tentativas += 1
    if tentativas == 5:
        print("conectou")
        break
else:
    print("desistiu depois de", tentativas, "tentativas")
desistiu depois de 3 tentativas

Este é o idioma da retentativa: o break é o sucesso, o else é o esgotamento das tentativas. Sem ele, seria preciso uma variável sucesso = False e um if depois do laço.

Dito isso: o else de laço divide opiniões, e com razão — a palavra sugere a coisa errada. A recomendação honesta é usá-lo quando ele elimina uma bandeira, sempre com um comentário ou um nome de função que deixe claro o que “sem break” significa ali; e não usá-lo em código que passa por muita gente diferente.

17.4 match: casar com a forma do dado

Desde o Python 3.10 (PEP 634 a 636), o match compara um valor contra padrões estruturais. Ele não é o switch de C: não é uma cadeia de igualdades, é desestruturação com teste embutido.

O caso que justifica a instrução é o de dados que chegam de fora — JSON de uma API, evento de fila, linha de comando:

def descrever(evento):
    match evento:
        case {"tipo": "alarme", "onu": onu, "nivel": nivel} if nivel < -28:
            return f"CRITICO {onu} em {nivel} dBm"
        case {"tipo": "alarme", "onu": onu}:
            return f"alarme comum em {onu}"
        case {"tipo": "reboot", "onu": onu, **resto}:
            return f"reboot de {onu} (extras: {resto})"
        case {"tipo": tipo}:
            return f"evento desconhecido: {tipo}"
        case _:
            return "sem tipo"


eventos = [
    {"tipo": "alarme", "onu": "onu-02", "nivel": -31.2},
    {"tipo": "alarme", "onu": "onu-01", "nivel": -19.5},
    {"tipo": "reboot", "onu": "onu-05", "causa": "queda de energia"},
    {"tipo": "sync"},
    {"origem": "olt"},
]
for e in eventos:
    print(descrever(e))
CRITICO onu-02 em -31.2 dBm
alarme comum em onu-01
reboot de onu-05 (extras: {'causa': 'queda de energia'})
evento desconhecido: sync
sem tipo

Em cinco case estão: teste de valor literal ("alarme"), extração de campos para variáveis (onu, nivel), guarda (if nivel < -28), captura do resto do dicionário (**resto) e curinga (_). Escrever isso com if e .get() daria três vezes mais linhas, e cada acesso teria que ser defendido contra chave ausente.

Dois pontos importantes sobre padrão de mapeamento: ele casa por subconjunto — {"tipo": "alarme"} casa com um dicionário que tenha outras chaves além dessa —, e a ordem dos case importa como na cadeia de elif, então o padrão mais específico vem primeiro. Foi por isso que a guarda if nivel < -28 ficou no topo.

17.4.1 Padrões de sequência

def roteia(comando):
    match comando.split():
        case ["listar"]:
            return "lista tudo"
        case ["listar", olt]:
            return f"lista a {olt}"
        case ["reiniciar", *onus] if onus:
            return f"reinicia {len(onus)}: " + ", ".join(onus)
        case ["sair" | "quit" | "exit"]:
            return "tchau"
        case []:
            return "comando vazio"
        case _:
            return "nao entendi"


for c in ["listar", "listar olt-sul", "reiniciar onu-01 onu-02", "quit", "", "voar"]:
    print(f"{c!r:<28} -> {roteia(c)}")
'listar'                     -> lista tudo
'listar olt-sul'             -> lista a olt-sul
'reiniciar onu-01 onu-02'    -> reinicia 2: onu-01, onu-02
'quit'                       -> tchau
''                           -> comando vazio
'voar'                       -> nao entendi

O padrão de sequência casa por tamanho e posição: ["listar"] só casa com lista de um elemento. O *onus absorve o resto, | é alternativa, e a guarda if onus rejeita reiniciar sem argumento.

Uma armadilha específica: str e bytes não casam como sequência, mesmo sendo sequências.

match "abc":
    case [a, b, c]:
        print("string casou como sequencia?", a, b, c)
    case str() as s:
        print("string nao e sequencia para o match:", s)
string nao e sequencia para o match: abc

A exceção é deliberada: sem ela, case [x] casaria com qualquer string de um caractere, e ninguém quer isso.

17.4.2 Padrões de classe

from dataclasses import dataclass


@dataclass
class Ponto:
    x: float
    y: float


def onde(p):
    match p:
        case Ponto(x=0, y=0):
            return "origem"
        case Ponto(x=0, y=y):
            return f"eixo vertical em y={y}"
        case Ponto(x=x, y=0):
            return f"eixo horizontal em x={x}"
        case Ponto():
            return "fora dos eixos"
        case _:
            return "nao e um ponto"


for p in [Ponto(0, 0), Ponto(0, 3), Ponto(2, 0), Ponto(1, 1), "abc"]:
    print(onde(p))
origem
eixo vertical em y=3
eixo horizontal em x=2
fora dos eixos
nao e um ponto

Ponto(x=0, y=0) não é uma chamada: é um padrão que testa o tipo e os atributos. Ponto() testa só o tipo, e é o isinstance escrito como padrão. Também funciona com os tipos embutidos, o que dá validação de tipo de graça:

match (200, "ok"):
    case (int(codigo), str(texto)):
        print("codigo", codigo, "texto", texto)
codigo 200 texto ok

17.4.3 O erro que todo mundo comete uma vez

Um nome simples num padrão nunca é uma comparação: é uma captura.

CRITICO = -28.0


def faixa(nivel):
    match nivel:
        case CRITICO:
            return f"casou com o limite? CRITICO agora vale {CRITICO}"


print(faixa(-19.5))
print("CRITICO no modulo:", CRITICO)
casou com o limite? CRITICO agora vale -19.5
CRITICO no modulo: -28.0

O case CRITICO: casou com −19,5 — casaria com qualquer coisa — e ligou o nome CRITICO ao valor recebido, como variável local. A constante do módulo continua intacta, o que torna o bug ainda mais difícil de ver: o teste “a constante mudou?” não acusa nada.

Quando há um case depois, o Python detecta e recusa o programa:

CRITICO = -28.0


def faixa(nivel):
    match nivel:
        case CRITICO:
            return "no limite"
        case _:
            return "outro"
  File "/home/vitor/lab17/captura2.py", line 6
    case CRITICO:
         ^^^^^^^
SyntaxError: name capture 'CRITICO' makes remaining patterns unreachable

A mensagem é excelente e diz o nome do problema: name capture. A correção é usar um nome pontilhado, que o match trata como valor:

class Limiar:
    CRITICO = -28.0
    SATURACAO = -8.0


def faixa(nivel):
    match nivel:
        case Limiar.CRITICO:
            return "exatamente no limite critico"
        case Limiar.SATURACAO:
            return "exatamente no limite de saturacao"
        case _:
            return "entre os limites"


for n in (-28.0, -8.0, -19.5):
    print(f"{n:>7}  {faixa(n)}")
  -28.0  exatamente no limite critico
   -8.0  exatamente no limite de saturacao
  -19.5  entre os limites

Uma classe simples, um Enum ou um módulo importado — qualquer coisa com ponto no meio serve. É a razão de o match combinar tão bem com enum.Enum.

17.5 🐍 Jeito Pythônico

break aninhado quer virar função. Extraia a busca e use return; ele sai de todos os níveis e ainda dá um nome ao que o laço faz.

continue como guarda no topo do laço. Trate e descarte o caso ruim na primeira linha, deixe o trabalho útil sem indentação.

else de laço só para eliminar bandeira. É o par de break numa busca ou numa retentativa. Se você precisou explicar o else em comentário longo, uma função com return é mais clara.

Não use match como switch. Para comparar uma variável contra constantes, o dicionário do Capítulo 15 continua melhor. match se paga quando há estrutura: sequência de tamanho variável, dicionário aninhado, tipos diferentes no mesmo canal.

# antipadrão: match usado como escada de igualdades
match plano:
    case "basico":
        preco = 79.90
    case "turbo":
        preco = 129.90
# pythônico
TARIFAS = {"basico": 79.90, "turbo": 129.90}
preco = TARIFAS[plano]

Constante em case sempre com ponto. case Limiar.CRITICO:, case Status.ATIVO:. Nome simples é captura, e captura silenciosa.

Termine o match com case _: quando a entrada vem de fora. Sem curinga, um valor não previsto simplesmente não faz nada — e “não faz nada” é o pior desfecho possível para dado malformado.

Nada de for ... else combinado com continue para simular fluxo. O bloco for/else/continue/break da busca aninhada existe, funciona e é ilegível; a função com return faz o mesmo em metade das linhas.

Sobre versões:

  • Python 3.10 — match/case (PEP 634, 635 e 636). É a mudança de sintaxe mais visível da série 3.x recente.
  • Python 3.11 — mensagens de erro do match mais precisas, incluindo o name capture acima.
  • Python 3.12 — o compilador passou a otimizar melhor o despacho de match sobre literais.
  • break, continue e o else de laço existem desde sempre e não mudaram.

"""Console de operacao: le comandos de um arquivo e despacha com match."""

from pathlib import Path

from rede import REDE


def executar(comando):
    """Devolve (mensagem, encerrar)."""
    match comando.split():
        case [] | ["#", *_]:
            return None, False
        case ["listar"]:
            return " ".join(REDE), False
        case ["listar", olt] if olt in REDE:
            onus = REDE[olt]
            return f"{olt}: " + ", ".join(f"{k}={v}" for k, v in onus.items()), False
        case ["listar", olt]:
            return f"OLT desconhecida: {olt}", False
        case ["nivel", onu]:
            for olt, onus in REDE.items():
                if onu in onus:
                    return f"{onu} em {olt}: {onus[onu]} dBm", False
            return f"{onu} nao encontrada", False
        case ["criticas", *_]:
            achadas = [
                f"{olt}/{onu}"
                for olt, onus in REDE.items()
                for onu, nivel in onus.items()
                if nivel < -28
            ]
            return ("criticas: " + ", ".join(achadas)) if achadas else "nenhuma", False
        case ["sair" | "quit"]:
            return "encerrando", True
        case _:
            return f"comando invalido: {comando!r}", False


if __name__ == "__main__":
    linhas = Path("comandos.txt").read_text(encoding="utf-8").splitlines()
    for numero, linha in enumerate(linhas, start=1):
        mensagem, encerrar = executar(linha)
        if mensagem is None:
            continue
        print(f"{numero:>2}| {mensagem}")
        if encerrar:
            break
    else:
        print("fim do arquivo sem comando de saida")

17.7 Resumo

  • break sai do laço mais interno — não existe break com rótulo. Para sair de laços aninhados, extraia uma função e use return.
  • continue pula para a próxima volta e é a forma idiomática de filtrar entrada no topo do laço; no while com contador, é gerador de laço infinito.
  • O else de laço deveria chamar-se nobreak: roda quando o laço termina naturalmente, inclusive quando ele não dá volta nenhuma, e não roda depois de um break.
  • O par break/else elimina a variável-bandeira em buscas e retentativas.
  • match (3.10+) casa estrutura, não valor: literais, sequências por tamanho e posição, mapeamentos por subconjunto, classes por tipo e atributos, alternativas com |, guardas com if e o curinga _.
  • str e bytes não casam como sequência, por decisão de projeto.
  • Nome simples em case é captura, não comparação: casa com tudo e rebatiza o valor. Constante só com nome pontilhado (Limiar.CRITICO, Status.ATIVO).
  • Terminar o match com case _: transforma “não fez nada” em erro visível, e faz o compilador detectar capturas acidentais.
