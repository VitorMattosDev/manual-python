15  Condicionais: if, elif, else e a expressão condicional

O sistema de monitoramento de uma rede de fibra recebe, a cada cinco minutos, o nível óptico de milhares de ONUs. A faixa saudável vai de −28 dBm a −8 dBm: abaixo disso o sinal está fraco demais para o equipamento entender, acima disso está forte demais e satura o receptor. Alguém escreveu o alerta:

def alerta(nivel):
    if nivel < -28 or -8:
        return "fora de faixa"
    return "ok"

Lê-se em voz alta como português correto — “se o nível for menor que −28 ou −8” — e o resultado é este:

for n in (-20.0, -3.0, -30.0):
    print(n, alerta(n))
-20.0 fora de faixa
-3.0 fora de faixa
-30.0 fora de faixa

Todas as ONUs da rede aparecem fora de faixa. A equipe de campo passou uma semana perseguindo alarme falso antes de alguém rodar isto:

print(bool(-8))
print((-20.0 < -28) or -8)
True
-8

O or não distribui a comparação. O Python avalia nivel < -28 (falso), passa para o segundo operando, encontra -8, e -8 é um objeto verdadeiro — como qualquer número diferente de zero, pela regra do Capítulo 11. A condição inteira é sempre verdadeira, e o if sempre entra. Não houve erro de sintaxe, não houve traceback, não houve aviso: o código está perfeitamente correto para o Python e perfeitamente errado para a rede.

A forma certa é uma cadeia de comparação, e ela também é mais curta:

def alerta(nivel):
    if not -28 <= nivel <= -8:
        return "fora de faixa"
    return "ok"


for n in (-20.0, -3.0, -30.0, -8.0):
    print(n, alerta(n))
-20.0 ok
-3.0 fora de faixa
-30.0 fora de faixa
-8.0 ok

Este capítulo é sobre decidir: a sintaxe do if, o que exatamente o Python considera verdadeiro na hora de decidir, e as três ou quatro construções que substituem escadas de condicionais por código que se lê de uma vez.

15.1 if, elif, else

A estrutura é a que se espera, com a indentação do Capítulo 6 delimitando os blocos e os dois-pontos fechando cada cabeçalho:

nivel = -19.5

if nivel < -28:
    estado = "critico"
elif nivel < -25:
    estado = "atencao"
elif nivel <= -8:
    estado = "normal"
else:
    estado = "alto demais"

print(estado)
normal

Três detalhes que importam mais do que parecem:

  • elif é uma palavra só. Não existe else if em Python, e escrever else: seguido de um if indentado funciona, mas empurra tudo um nível para a direita.
  • elif e else são opcionais, e pode haver quantos elif você quiser. Um if sozinho é uma condicional completa.
  • A primeira condição verdadeira vence. As de baixo nem chegam a ser avaliadas — e isso não é detalhe de desempenho, é semântica.

Dá para ver a parada acontecendo com uma função que anuncia quando é chamada:

def testa(rotulo, valor):
    print(f"testando {rotulo}")
    return valor


if testa("A", False):
    print("A venceu")
elif testa("B", True):
    print("B venceu")
elif testa("C", True):
    print("C venceu")
else:
    print("nenhuma")
testando A
testando B
B venceu

C era verdadeiro e nunca foi testado. Se testa("C", ...) gravasse no banco, a gravação não teria acontecido. Condição com efeito colateral é uma armadilha justamente por isso.

Como consequência prática: ordem importa e ordem esconde bug. Numa escada de faixas numéricas, trocar duas linhas de lugar muda o resultado sem mudar nada visível. Se você inverter os dois primeiros elif do exemplo acima, -26.4 continua caindo em atencao, mas -31.0 também — porque -31 < -25 é verdadeiro e a linha do critico deixou de ser alcançável para todo mundo.

15.2 O que o if considera verdadeiro

O if não exige um bool. Ele chama o protocolo de valor-verdade do Capítulo 11 em qualquer objeto:

for v in (0, 0.0, 0j, "", b"", [], (), {}, set(), None, range(0), "0", [0], -1):
    print(f"{v!r:>10}  {bool(v)}")
         0  False
       0.0  False
        0j  False
        ''  False
       b''  False
        []  False
        ()  False
        {}  False
     set()  False
      None  False
range(0, 0)  False
       '0'  True
       [0]  True
        -1  True

Zero de qualquer tipo numérico, contêiner vazio e None são falsos; o resto é verdadeiro. Repare em "0" e [0]: a string com o dígito zero e a lista que contém um zero são verdadeiras, porque não estão vazias.

Isso torna idiomático testar contêiner diretamente:

portas = []

if portas:
    print("tem porta")
else:
    print("lista vazia")
lista vazia

if portas: em vez de if len(portas) > 0:. É mais curto, funciona para qualquer sequência e não força o objeto a calcular um comprimento que pode ser caro.

E é aqui que mora o segundo bug clássico do capítulo. Quando 0 é um valor legítimo, if not x: confunde “não informado” com “informado como zero”:

def desconto_ruim(p=None):
    if not p:
        p = 10
    return p


def desconto(p=None):
    if p is None:
        p = 10
    return p


for arg in (0, 5, None):
    print(f"{str(arg):>4}  ruim={desconto_ruim(arg):>3}  certo={desconto(arg):>3}")
   0  ruim= 10  certo=  0
   5  ruim=  5  certo=  5
None  ruim= 10  certo= 10

O cliente que tinha desconto de 0% recebeu 10%. A regra é curta: para testar ausência, use is None; para testar vazio, use o valor-verdade. Vale também para string ("" é um nome vazio informado, None é nome não informado) e para lista ([] é “consultei e não achou nada”, None é “não consultei”).

O is aqui é o mesmo do Capítulo 8: compara identidade, e None é um singleton, então is None é a comparação certa — e mais rápida que == None, que ainda por cima pode ser sequestrada por uma classe que defina __eq__.

15.3 Comparações encadeadas

O Python permite escrever a desigualdade dupla como se escreve em matemática:

x = 5
print(1 < x < 10)
print(1 < x and x < 10)
True
True

As duas formas são equivalentes em resultado, mas não em execução: na cadeia, o operando do meio é avaliado uma vez só.

def um():
    print("avaliou uma vez")
    return 5


print(0 < um() < 10)
avaliou uma vez
True

Escrito como 0 < um() and um() < 10, a função seria chamada duas vezes. O bytecode mostra o truque — o Python duplica o valor na pilha em vez de recalcular:

import dis

dis.dis("a < b < c")
  0           RESUME                   0

  1           LOAD_NAME                0 (a)
              LOAD_NAME                1 (b)
              SWAP                     2
              COPY                     2
              COMPARE_OP               2 (<)
              COPY                     1
              TO_BOOL
              POP_JUMP_IF_FALSE        5 (to L1)
              POP_TOP
              LOAD_NAME                2 (c)
              COMPARE_OP               2 (<)
              RETURN_VALUE
      L1:     SWAP                     2
              POP_TOP
              RETURN_VALUE

O POP_JUMP_IF_FALSE é o curto-circuito: se a primeira comparação falha, c nunca é carregado.

A cadeia funciona com qualquer operador de comparação e com mais de dois:

print(-28 <= -19.5 <= -8)
print("a" < "b" < "c")
print(1 == 1 != 2)
True
True
True

O último merece atenção: 1 == 1 != 2 significa 1 == 1 and 1 != 2, não (1 == 1) != 2. Encadear operadores de igualdade com operadores de ordem é legal e quase sempre confuso — use quando for uma faixa (a <= x <= b) e evite o resto.

15.4 Cláusulas de guarda em vez de pirâmide

Condicional aninhada cresce para a direita e o código fica difícil de seguir depois do terceiro nível:

def registrar_aninhado(leitura):
    if leitura is not None:
        if leitura.get("nivel") is not None:
            if -28 <= leitura["nivel"] <= -8:
                return "ok"
            else:
                return "fora de faixa"
        else:
            return "sem nivel"
    else:
        return "sem leitura"

O caso normal — o "ok" — é o mais escondido de todos, e cada else está a dezenas de colunas do if que ele fecha. A mesma função, escrita com cláusulas de guarda, trata cada caso excepcional na hora e devolve:

def registrar(leitura):
    if leitura is None:
        return "sem leitura"
    nivel = leitura.get("nivel")
    if nivel is None:
        return "sem nivel"
    if not -28 <= nivel <= -8:
        return "fora de faixa"
    return "ok"
casos = [None, {}, {"nivel": -19.5}, {"nivel": -31.0}]
for c in casos:
    print(f"{str(c):<18} {registrar_aninhado(c):<14} {registrar(c)}")
None               sem leitura    sem leitura
{}                 sem nivel      sem nivel
{'nivel': -19.5}   ok             ok
{'nivel': -31.0}   fora de faixa  fora de faixa

Idênticas no comportamento, distantes na legibilidade. A versão com guardas tem um nível de indentação, lê-se de cima para baixo como uma lista de pré-condições e termina no caminho feliz.

Numa função sem return — dentro de um laço, por exemplo — a guarda usa continue, que é assunto do capítulo 17.

15.5 A expressão condicional

if é uma instrução: ele não produz valor, então não cabe dentro de uma expressão. Quando você precisa escolher um valor, o operador ternário do Python resolve:

nivel = -19.5
rotulo = "ok" if -28 <= nivel <= -8 else "fora"
print(rotulo)
ok

A ordem é valor_se_verdadeiro if condição else valor_se_falso — a condição fica no meio, ao contrário do ? : de C e JavaScript. É estranho no primeiro dia e natural no terceiro, porque se lê como português: “ok”, se o nível estiver na faixa; senão, “fora”.

O else é obrigatório. Não existe expressão condicional sem alternativa — o Python precisa produzir um valor nos dois caminhos.

Onde ele rende de verdade é dentro de outra expressão, em lugares onde um if de bloco não caberia:

print([("ok" if -28 <= n <= -8 else "fora") for n in (-20, -3, -30)])
['ok', 'fora', 'fora']

Dentro de uma f-string do Capítulo 13, cuidando de plural:

for falta in (0, 1, 3):
    print(f'{falta} porta{"s" if falta != 1 else ""} livre{"s" if falta != 1 else ""}')
0 portas livres
1 porta livre
3 portas livres

E para tratar ausência sem quebrar a formatação:

valores = {"onu-01": -19.5, "onu-02": None, "onu-03": -31.0}
for nome, n in valores.items():
    print(f"{nome}: {'sem leitura' if n is None else f'{n:.1f} dBm'}")
onu-01: -19.5 dBm
onu-02: sem leitura
onu-03: -31.0 dBm

Ternários aninhados são legais e funcionam:

n = -31.0
print("critico" if n < -28 else "atencao" if n < -25 else "ok")
critico

Funciona, e é o limite. Com quatro faixas isso vira uma linha que ninguém revisa direito — a partir daí, uma função com cadeia de if e return é mais barata de ler e de testar.

15.6 O operador morsa em condições

Desde o Python 3.8 (PEP 572), := atribui dentro de uma expressão. O caso que justifica o operador é exatamente o do if: você precisa do resultado de uma chamada tanto para testar quanto para usar.

import re

registro = "onu-07 nivel=-24.3 status=up"
if (m := re.search(r"nivel=(-?\d+\.\d+)", registro)):
    print("nivel:", float(m.group(1)))
else:
    print("sem nivel")
nivel: -24.3

Sem ele, ou você chama re.search duas vezes, ou atribui antes do if e deixa a variável viva num escopo mais largo do que precisa. Com ele, m nasce e é testado na mesma linha.

Duas regras de higiene: os parênteses em torno do := são quase sempre dispensáveis, mas deixá-los evita ambiguidade de precedência e sinaliza a atribuição para quem lê; e := não substitui = na atribuição comum — usar o morsa fora de uma expressão é SyntaxError.

15.7 Escada de elif ou tabela?

Quando toda a cadeia testa igualdade contra a mesma variável, ela não é lógica: é uma tabela escrita como código.

def taxa_elif(plano):
    if plano == "basico":
        return 79.90
    elif plano == "turbo":
        return 129.90
    elif plano == "gamer":
        return 199.90
    else:
        raise ValueError(f"plano desconhecido: {plano!r}")

Um dicionário diz o mesmo em três linhas, e o preço vira dado em vez de código:

TARIFAS = {"basico": 79.90, "turbo": 129.90, "gamer": 199.90}

print(TARIFAS["turbo"])
print(TARIFAS.get("empresarial", 0.0))
129.9
0.0

Um dicionário de funções faz o mesmo com comportamento no lugar do valor — é o dispatch table, e é o que substitui o switch que o Python não tem. Isso vale para igualdade contra constantes. Quando as condições são faixas, testes compostos ou desestruturação de dados, a escada de if continua sendo a resposta certa — ou o match, que estrutura o caso de desestruturação e é o assunto do capítulo 17.

15.8 🐍 Jeito Pythônico

Teste o objeto, não o comprimento dele. if portas: em vez de if len(portas) > 0:, if not texto: em vez de if texto == "":. A PEP 8 é explícita nesse ponto.

Para ausência, is None. Sempre que 0, "" ou [] forem valores legítimos, if x is None: é a única forma correta de perguntar “veio alguma coisa?”. == None funciona por acidente e not x funciona até o dia em que alguém passa zero.

Compare em cadeia. -28 <= nivel <= -8 é mais curto, avalia o meio uma vez e não tem como virar o bug do or -8 da abertura.

Prefira guardas a aninhamento. Trate os casos excepcionais no começo, saia cedo, e deixe o caminho normal sem indentação nenhuma. Três níveis de if dentro de if é o sinal de que a função quer virar duas.

Não escreva if x == True:. É redundante e é sutilmente diferente de if x: para objetos que não são bool. Pela mesma razão, if x is True: só se você realmente quer o singleton True e não “algo verdadeiro” — o que é raro.

# antipadrão
if usuario.ativo == True:
    ...
if len(erros) != 0:
    ...
if resultado != None:
    ...
# pythônico
if usuario.ativo:
    ...
if erros:
    ...
if resultado is not None:
    ...

Não faça a mesma atribuição nos dois ramos. Um if/else que só muda o valor de uma variável é uma expressão condicional disfarçada:

# antipadrão
if -28 <= nivel <= -8:
    rotulo = "ok"
else:
    rotulo = "fora"
# pythônico
rotulo = "ok" if -28 <= nivel <= -8 else "fora"

Ternário só quando cabe numa linha e numa leitura. A partir de dois else encadeados, escreva uma função.

Dicionário no lugar de escada de igualdades. Se todos os testes são variavel == constante, a estrutura de dados certa é um dict.

Sobre versões:

  • Python 3.8 — operador morsa := (PEP 572), que tornou o if (m := ...) idiomático.
  • Python 3.10 — instrução match/case (PEP 634), para os casos em que a decisão é sobre a forma do dado, não sobre um valor escalar.
  • Python 3.12 — mensagens de erro de sintaxe mais precisas para if sem dois-pontos e para = onde se queria ==, o que encurta a caçada descrita no Capítulo 7.

"""Classifica o nivel optico de uma ONU em faixas operacionais."""

CRITICO = -28.0
ATENCAO = -25.0
SATURACAO = -8.0


def classificar(nivel):
    if nivel is None:
        return "sem leitura"
    if nivel < CRITICO:
        return "critico"
    if nivel < ATENCAO:
        return "atencao"
    if nivel <= SATURACAO:
        return "normal"
    return "saturado"


if __name__ == "__main__":
    for n in (None, -31.0, -26.4, -19.5, -3.0):
        print(f"{str(n):>7}  {classificar(n)}")

"""Relatorio de niveis opticos: classifica cada ONU e resume por faixa."""

import csv
from collections import Counter
from pathlib import Path

from classificar import classificar

ACAO = {
    "critico": "abrir chamado de campo",
    "atencao": "agendar inspecao",
    "normal": "",
    "saturado": "instalar atenuador",
    "sem leitura": "verificar se a ONU responde",
}


def ler(caminho):
    texto = Path(caminho).read_text(encoding="utf-8")
    for linha in csv.DictReader(texto.splitlines(), delimiter=";"):
        bruto = linha["nivel"].strip()
        yield linha["onu"], (float(bruto) if bruto else None)


if __name__ == "__main__":
    contagem = Counter()
    for onu, nivel in ler("leituras.csv"):
        faixa = classificar(nivel)
        contagem[faixa] += 1
        medida = "  ---  " if nivel is None else f"{nivel:>7.1f}"
        print(f"{onu}  {medida}  {faixa:<12} {ACAO[faixa]}")

    print("-" * 52)
    problemas = sum(v for k, v in contagem.items() if k != "normal")
    print(f"{contagem.total()} ONUs, {problemas} exigem acao")
    for faixa, n in contagem.most_common():
        print(f"  {faixa:<12} {n}")

15.10 Resumo

  • if/elif/else é avaliado de cima para baixo e para no primeiro teste verdadeiro; as condições abaixo não são avaliadas, então ordem é semântica e condição com efeito colateral é armadilha.
  • if aceita qualquer objeto e aplica o valor-verdade: zero de qualquer tipo, contêiner vazio e None são falsos. "0" e [0] são verdadeiros.
  • Para ausência, is None; para vazio, o valor-verdade. Confundir os dois é o bug que transforma desconto zero em desconto padrão.
  • a <= x <= b avalia x uma única vez e curto-circuita. x < a or b não é comparação com dois limites — é o bug da abertura.
  • Cláusulas de guarda com return antecipado substituem pirâmides de if aninhado: um nível de indentação e o caminho normal no fim, sem else.
  • A expressão condicional A if cond else B produz valor e cabe onde um bloco não caberia (f-string, compreensão, argumento). O else é obrigatório e o aninhamento tem limite de um.
  • := (3.8) atribui dentro da condição, evitando a chamada dupla no par testar-e-usar.
  • Escada de elif comparando a mesma variável com constantes é um dicionário disfarçado; faixas e formas de dados continuam sendo if ou match.
