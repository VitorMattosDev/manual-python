41  Classes, instâncias e o self

O coletor começou com três listas paralelas, porque três listas paralelas resolvem o problema no primeiro dia:

ids = ["onu-00042", "onu-00043", "onu-00044"]
potencias = [-21.4, -29.8, -18.2]
portas = ["1/1/1", "1/1/2"]           # alguém esqueceu uma

for i, ident in enumerate(ids):
    print(f"{ident} {potencias[i]} dBm porta {portas[i]}")
onu-00042 -21.4 dBm porta 1/1/1
onu-00043 -29.8 dBm porta 1/1/2
Traceback (most recent call last):
  File "/home/vitor/lab41/paralelas.py", line 6, in <module>
    print(f"{ident} {potencias[i]} dBm porta {portas[i]}")
                                              ~~~~~~^^^
IndexError: list index out of range

O erro aponta para a linha do print, que não tem defeito nenhum. O defeito é estrutural: nada no programa diz que o item i das três listas é o mesmo equipamento. A relação existe só na cabeça de quem escreveu, e some na primeira manutenção. Um dicionário por ONU melhora, mas continua sem lugar para a regra de negócio — a potência abaixo da qual o cliente reclama —, que acaba espalhada em if repetido por todo o programa.

Uma classe resolve os dois problemas de uma vez: amarra os dados que andam juntos e dá endereço ao comportamento que opera sobre eles. Este capítulo abre o Volume 7 mostrando o que exatamente o interpretador cria quando você escreve class, onde cada atributo mora e por que o primeiro parâmetro de todo método se chama self.

41.1 A primeira classe

class ONU:
    def __init__(self, ident, potencia, porta):
        self.ident = ident
        self.potencia = potencia
        self.porta = porta

    def critica(self):
        return self.potencia < -28.0


a = ONU("onu-00042", -21.4, "1/1/1")
b = ONU("onu-00043", -29.8, "1/1/2")
onu-00042 -21.4 False
onu-00043 -29.8 True
<__main__.ONU object at 0x79f0b0347230>
<class '__main__.ONU'> True

Os três dados agora viajam grudados, e a regra tem um nome. Um objeto sabe responder se está crítico; ninguém precisa lembrar do -28.0 na hora de escrever o relatório.

Duas coisas na saída merecem atenção desde já. ONU("onu-00042", ...) não chama __init__ diretamente — chamar a classe cria um objeto vazio e depois passa esse objeto para __init__ como primeiro argumento. E o print(a) sem mais nada dá <__main__.ONU object at 0x...>, que é a representação de fábrica: o nome do módulo, o nome da classe e o endereço de memória. Isso se resolve com __repr__, mais adiante.

41.2 O corpo da classe é código que roda

O class não é declaração; é uma instrução executável, como o def. O corpo roda uma vez, no momento da definição, num namespace próprio:

print("antes do class")


class Exemplo:
    print("  o corpo da classe roda agora")
    LIMITE = -28.0
    print(f"  e enxerga o próprio namespace: LIMITE = {LIMITE}")

    def metodo(self):
        print("  o corpo do método só roda quando chamado")


print("depois do class")
antes do class
  o corpo da classe roda agora
  e enxerga o proprio namespace: LIMITE = -28.0
depois do class
Exemplo e um objeto: <class '__main__.Exemplo'>
do tipo           : <class 'type'>
com um namespace  : ['__module__', '__firstlineno__', 'LIMITE', 'metodo', '__static_attributes__', '__dict__']

Ao terminar, o Python empacota aquele namespace num objeto e amarra ao nome Exemplo. Repare no type(Exemplo): é type. A classe é um objeto — pode ser guardada em lista, passada como argumento, devolvida por função. É a mesma cidadania de primeira classe que as funções têm desde o Capítulo 21.

Os nomes __firstlineno__ e __static_attributes__ no namespace são novidade do Python 3.13: o primeiro guarda a linha da definição, o segundo os atributos que o compilador viu sendo atribuídos em self. Em versões anteriores eles não aparecem.

41.3 Onde cada atributo mora

Este é o modelo mental que decide quase tudo em orientação a objetos no Python: cada instância tem seu próprio dicionário, e a classe tem outro.

class ONU:
    LIMITE = -28.0                     # atributo de classe

    def __init__(self, ident, potencia):
        self.ident = ident             # atributos de instância
        self.potencia = potencia

    def critica(self):
        return self.potencia < self.LIMITE
a.__dict__    : {'ident': 'onu-00042', 'potencia': -21.4}
b.__dict__    : {'ident': 'onu-00043', 'potencia': -29.8}
LIMITE na inst: False
LIMITE na cls : True
a.LIMITE      : -28.0

a.LIMITE funciona, mas LIMITE não está em a.__dict__. A busca é em cascata: primeiro a instância, depois a classe, depois as superclasses (assunto do Capítulo 43). Escrever, porém, não segue a mesma cascata — atribuir sempre grava na instância:

depois de mudar na classe: -25.0 -25.0
a.LIMITE      : -30.0   b.LIMITE: -25.0
a.__dict__    : {'ident': 'onu-00042', 'potencia': -21.4, 'LIMITE': -30.0}
depois do del : -25.0

Mudar ONU.LIMITE mudou para as duas instâncias, porque nenhuma tinha cópia própria. Atribuir a.LIMITE = -30.0 criou uma entrada em a.__dict__ que sombreia a da classe — só para a. E del a.LIMITE remove o sombreamento, revelando de novo o valor da classe. É a mesma assimetria entre leitura e escrita da regra LEGB do Capítulo 20, aplicada a objetos.

41.3.1 A armadilha do atributo mutável de classe

A assimetria acima é inofensiva com números e strings, porque atribuir cria a cópia local. Com uma lista, ninguém atribui — muta:

class OLTRuim:
    onus = []                          # ARMADILHA: compartilhado

    def registrar(self, ident):
        self.onus.append(ident)        # não atribui: muta a lista da classe
x.onus: ['onu-00042', 'onu-00043']
y.onus: ['onu-00042', 'onu-00043']
mesma lista? True

Duas OLTs distintas, uma lista só. self.onus.append(...) lê self.onus (cascata: acha na classe) e chama append no objeto encontrado. Nunca houve atribuição, então nunca houve cópia por instância. É a mesma armadilha do argumento padrão mutável do Capítulo 19, com outra roupa.

A correção é criar a lista no __init__, onde há uma execução por instância:

class OLT:
    def __init__(self):
        self.onus = []                 # uma lista por instância
p.onus: ['onu-00042']  q.onus: ['onu-00043']

Regra prática: atributo de classe só para valor imutável e realmente compartilhado — constantes, limites, contadores lidos com o nome da classe. Estado mutável nasce no __init__.

41.4 O self desmistificado

self não é palavra reservada. É só o nome que a comunidade dá ao primeiro parâmetro, e o interpretador o preenche por você porque o acesso a.descrever produz um objeto diferente da função original:

print("pela instância :", a.descrever())
print("pela classe    :", ONU.descrever(a))
print("com argumento  :", ONU.descrever(a, "equipamento"))
pela instancia : ONU onu-00042
pela classe    : ONU onu-00042
com argumento  : equipamento onu-00042

na classe      : <function ONU.descrever at 0x73d09a75f4c0>
na instancia   : <bound method ONU.descrever of <__main__.ONU object at 0x73d09a847230>>
__func__       : True
__self__       : True

ONU.descrever é uma função comum. a.descrever é um método ligado: um objeto que embrulha a função e a instância. Chamá-lo insere a na frente dos argumentos. Por isso a.descrever() e ONU.descrever(a) são a mesma chamada escrita de duas formas — e os atributos __func__ e __self__ mostram as duas metades do embrulho.

Duas consequências práticas. A primeira: um método ligado é um objeto autossuficiente, ótimo como callback, e ele segura a instância:

f = a.descrever
del a
print("o método ligado segura a instância:", f())
o metodo ligado segura a instancia: ONU onu-00042

O del a apagou o nome, não o objeto — f.__self__ ainda o referencia, e a contagem de referências do Capítulo 8 mantém tudo de pé.

A segunda: esquecer o self na definição produz um erro com número confuso.

class Errada:
    def metodo():
        return "não recebo nada"
TypeError: Errada.metodo() takes 0 positional arguments but 1 was given

“Zero esperados, um recebido” — mas você não passou argumento nenhum. O argumento é a instância, inserida pelo método ligado. Sempre que esse 1 was given aparecer numa chamada sem argumentos, o diagnóstico é self faltando.

E, para deixar claro que é convenção mesmo:

class Estranha:
    def metodo(eu):                    # 'self' é convenção, não palavra-chave
        return f"funciona, eu = {eu.__class__.__name__}"
funciona, eu = Estranha

Funciona — e não se escreve assim. Toda ferramenta do ecossistema (Ruff, mypy, o realce do editor) assume self, e fugir disso só cria atrito.

41.5 Dar uma cara ao objeto: __repr__ e __str__

A representação de fábrica é inútil em log e em depuração. Dois métodos resolvem:

class Com:
    def __init__(self, ident, potencia):
        self.ident = ident
        self.potencia = potencia

    def __repr__(self):
        return f"Com(ident={self.ident!r}, potencia={self.potencia!r})"

    def __str__(self):
        return f"{self.ident} @ {self.potencia} dBm"
sem __repr__: <__main__.Sem object at 0xADDR>
numa lista  : [<__main__.Sem object at 0xADDR>]
com __repr__: Com(ident='onu-00042', potencia=-21.4)
numa lista  : [Com(ident='onu-00042', potencia=-21.4)]
com __str__ : onu-00042 @ -21.4 dBm
no print    : onu-00042 @ -21.4 dBm
no f-string : onu-00042 @ -21.4 dBm / Com(ident='onu-00042', potencia=-21.4)

A divisão de trabalho é clara. __repr__ é para quem programa: sem ambiguidade, de preferência no formato que reconstruiria o objeto. __str__ é para quem lê a saída. Quando só um existe, __repr__ cobre os dois casos — o contrário não vale, e é por isso que __repr__ é o que se escreve primeiro.

Repare no detalhe que mais economiza tempo: dentro de uma lista, o Python usa sempre __repr__, nunca __str__. Um objeto sem __repr__ transforma qualquer coleção impressa em parede de endereços de memória. O !r no f-string força __repr__, e é o certo dentro do próprio __repr__ para que as strings saiam com aspas.

41.6 Igualdade é identidade, por padrão

a = ONU("onu-00042")
b = ONU("onu-00042")
a == b : False
a is b : False
a == a : True
num set: 2

Dois objetos com exatamente os mesmos dados são diferentes. O == de fábrica, herdado de object, compara endereço — é is com outro nome. Para muitos objetos isso é o certo (duas conexões abertas para o mesmo banco não são a mesma conexão), mas para um registro de dados quase nunca é.

Definir __eq__ obriga a definir __hash__ junto:

    def __eq__(self, outro):
        if not isinstance(outro, ONUComparavel):
            return NotImplemented
        return self.ident == outro.ident

    def __hash__(self):
        return hash(self.ident)
x == y : True
x is y : False
num set: 1

Declarar __eq__ faz o Python zerar o __hash__ herdado, e o objeto vira inutilizável como chave de dicionário ou elemento de conjunto — porque dois objetos iguais têm de ter o mesmo hash. Devolver NotImplemented (e não False) na comparação com tipo alheio é o protocolo correto: dá ao outro operando a chance de tentar, e só então o Python decide por False. O Capítulo 46 mostra o @dataclass, que gera os dois métodos de graça e é o que se usa na prática.

41.7 Instâncias aceitam atributos novos

a = ONU("onu-00042")
a.temperatura = 47.2                   # atributo que a classe nunca declarou
a.__dict__: {'ident': 'onu-00042', 'temperatura': 47.2}
AttributeError: 'ONU' object has no attribute 'temperatura'
getattr com padrao: None
hasattr           : False
depois do setattr : 44.0

O __dict__ é um dicionário comum, e nada impede acrescentar chaves. Isso é flexibilidade real — e fonte de bug de digitação silencioso, porque onu.potencia = -21.4 num objeto cujo atributo se chama potência cria um campo novo em vez de reclamar. O __slots__ do Capítulo 53 é a trava para quando isso importa.

getattr(obj, nome, padrão) e hasattr são a forma segura de perguntar; setattr escreve com o nome vindo de uma variável.

41.8 Contadores: o erro clássico do +=

class ONU:
    total = 0

    def __init__(self, ident):
        self.ident = ident
        ONU.total += 1                 # explícito na classe, não em self
instancias criadas: 3
com self.total += 1: 0  (nao contou nada)
cada instancia ficou com: 1

self.total += 1 é self.total = self.total + 1: lê da classe (0), soma 1, escreve na instância. Cada objeto acaba com o seu total = 1 e o contador da classe nunca sai do zero. Escrever ONU.total += 1 é a forma correta — e o @classmethod do Capítulo 45 dá a maneira idiomática de fazer isso sem repetir o nome da classe.

41.9 Juntando: o coletor com classes

class ONU:
    LIMITE_CRITICO = -28.0

    def __init__(self, ident, potencia, porta):
        self.ident = ident
        self.potencia = potencia
        self.porta = porta

    def critica(self):
        return self.potencia < self.LIMITE_CRITICO

    def __repr__(self):
        return f"ONU({self.ident!r}, {self.potencia!r}, {self.porta!r})"


class OLT:
    def __init__(self, nome):
        self.nome = nome
        self.onus = []

    def registrar(self, onu):
        self.onus.append(onu)
        return onu

    def criticas(self):
        return [o for o in self.onus if o.critica()]

    def relatorio(self):
        ruins = self.criticas()
        return f"{self.nome}: {len(self.onus)} ONUs, {len(ruins)} criticas"

    def __repr__(self):
        return f"OLT({self.nome!r}, {len(self.onus)} ONUs)"
OLT('olt-borda-01', 4 ONUs)
olt-borda-01: 4 ONUs, 2 criticas
   ONU('onu-00043', -29.8, '1/1/2')
   ONU('onu-00045', -31.7, '1/1/4')

Nada aqui é sofisticado, e é esse o ponto. As listas paralelas viraram uma lista de objetos; o -28.0 mora num lugar só; o relatório é uma linha. E LIMITE_CRITICO foi lido como self.LIMITE_CRITICO, não ONU.LIMITE_CRITICO — de propósito: assim uma subclasse pode baixar o limite sem reescrever o método, que é o assunto do Capítulo 43.

41.10 🐍 Jeito Pythônico

Classe quando dados e comportamento andam juntos. Um punhado de funções que recebem sempre o mesmo dicionário como primeiro argumento já é uma classe mal escrita. Por outro lado, uma classe com um método só e nenhum estado é uma função disfarçada — escreva a função.

# antipadrão
def critica(onu):
    return onu["potencia"] < -28.0

def descrever(onu):
    return f"{onu['ident']} @ {onu['potencia']}"
# pythônico: o dado que os dois recebem é o objeto
class ONU:
    def critica(self): ...
    def descrever(self): ...

Todo estado mutável nasce no __init__. Atributo de classe só para constante compartilhada. Lista, dicionário e conjunto no corpo da classe são o mesmo bug do argumento padrão mutável.

__repr__ em toda classe que você vai depurar — que são praticamente todas. O formato de referência é NomeDaClasse(campo=valor, ...), com !r nos valores. __str__ só quando a saída para pessoa é diferente da saída para quem programa.

self é o nome, sempre. Não invente; e não passe self explicitamente na chamada (a.metodo(a) é erro).

Não use __dict__ diretamente para ler ou escrever atributo. getattr, setattr e hasattr respeitam propriedades e descritores; obj.__dict__["x"] os atropela.

Nomeie o que é interno com um sublinhado à frente (self._buffer). É convenção, não proteção — o Capítulo 42 trata do assunto.

__eq__ e __hash__ andam em par. Definir só o primeiro torna o objeto não-hasheável. Na prática, use @dataclass (Capítulo 46) em vez de escrever os dois à mão.

Sobre versões:

  • Python 3.0 — as classes clássicas somem; toda classe herda de object, e não se escreve mais class C(object):.
  • Python 3.6 — a PEP 526 permite anotar atributos no corpo da classe (potencia: float), sem criar atributo de classe: a anotação sozinha só popula __annotations__.
  • Python 3.7 — @dataclass entra na biblioteca padrão e passa a ser o caminho normal para classe de dados.
  • Python 3.10 — match reconhece objetos por padrão de classe (case ONU(potencia=p)), usando __match_args__.
  • Python 3.13 — __firstlineno__ e __static_attributes__ aparecem no namespace da classe; o segundo lista os atributos que o compilador viu atribuídos em self.

41.12 Resumo

  • class é instrução executável: o corpo roda uma vez, na definição, e o namespace resultante vira um objeto. A classe é um objeto de tipo type, com a mesma cidadania de uma função.
  • Chamar a classe cria a instância e só então passa o objeto novo para __init__ como self. __init__ inicializa; não constrói.
  • Cada instância tem seu __dict__; a classe tem outro. A leitura de atributo desce a cascata instância → classe → bases; a escrita grava sempre na instância.
  • Por causa dessa assimetria, a.X = v sombreia o X da classe só para a, e del a.X revela o da classe de novo.
  • Atributo mutável no corpo da classe é compartilhado por todas as instâncias, porque self.lista.append(...) muta sem nunca atribuir. Estado mutável nasce no __init__.
  • self é convenção, não palavra-chave. O acesso a.metodo produz um método ligado, que embrulha a função (__func__) e a instância (__self__) e insere a segunda nos argumentos.
  • Esquecer o self na assinatura dá takes 0 positional arguments but 1 was given numa chamada sem argumentos — o 1 é a instância.
  • __repr__ é para quem programa e é o que as coleções usam; __str__ é para quem lê a saída. Com um só, escreva __repr__.
  • O == de fábrica compara identidade. Definir __eq__ anula o __hash__ herdado, então os dois andam em par.
  • self.contador += 1 num atributo de classe lê da classe e escreve na instância — o contador nunca anda. Use o nome da classe.

O próximo capítulo pega o ponto mais frágil do que ficou: nada impede alguém de escrever onu.potencia = "muito ruim" e quebrar o critica() três funções adiante. É aí que entram as propriedades e o encapsulamento.
