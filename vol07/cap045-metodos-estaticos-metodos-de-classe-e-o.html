45  Métodos estáticos, métodos de classe e o desenho da API

A ONU do Capítulo 42 valida o que recebe, mas quem a usa continua fazendo trabalho braçal em toda chamada:

linha = "onu-00042,-21.4,1/1/1"
ident, pot, porta = linha.split(",")
a = ONU(ident, float(pot), porta)

registro = {"ident": "onu-00043", "potencia": -29.8, "porta": "1/1/2"}
b = ONU(registro["ident"], registro["potencia"], registro["porta"])
ONU('onu-00042', -21.4, '1/1/1')
ONU('onu-00043', -29.8, '1/1/2')

Três linhas para transformar uma linha de CSV num objeto — e essas três linhas estão espalhadas por todo lugar que lê CSV. Quando o formato ganhar uma quarta coluna, todos esses pontos quebram, e o __init__ não pode ajudar porque só existe um por classe.

Python resolve isso com métodos que pertencem à classe e não à instância. Este capítulo mostra os três tipos de método, quando cada um cabe, e como eles se combinam para desenhar uma API que as pessoas conseguem usar sem ler o código-fonte.

45.1 Os três tipos, lado a lado

class Demo:
    def instancia(self, x):
        return f"instancia: self={type(self).__name__} x={x}"

    @classmethod
    def declasse(cls, x):
        return f"classe   : cls={cls.__name__} x={x}"

    @staticmethod
    def estatico(x):
        return f"estatico : sem primeiro argumento, x={x}"
instancia: self=Demo x=1
classe   : cls=Demo x=1
estatico : sem primeiro argumento, x=1

pela classe:
  TypeError: Demo.instancia() missing 1 required positional argument: 'x'
  classe   : cls=Demo x=1
  estatico : sem primeiro argumento, x=1

Os três funcionam chamados pela instância. Pela classe, só dois: o método de instância reclama, porque o self que o método ligado do Capítulo 41 inseria não existe — e repare que a mensagem culpa o x, não o self, que é o mesmo deslocamento de argumento de sempre.

A diferença está no que o Python coloca na frente dos argumentos:

o que sai do dict da classe:
  instancia  -> function
  declasse   -> classmethod
  estatico   -> staticmethod

depois do acesso por ponto:
  instancia  -> function
  declasse   -> method
  estatico   -> function

classmethod e staticmethod são objetos que embrulham a função no dicionário da classe. No acesso por ponto, o primeiro produz um método ligado à classe (por isso method), e o segundo devolve a função crua, sem embrulho nenhum.

45.2 @classmethod: construtores alternativos

Este é o uso que justifica o recurso:

class ONU:
    def __init__(self, ident, potencia, porta):
        self.ident = ident
        self.potencia = potencia
        self.porta = porta

    @classmethod
    def de_csv(cls, linha):
        ident, pot, porta = linha.strip().split(",")
        return cls(ident, float(pot), porta)

    @classmethod
    def de_dict(cls, registro):
        return cls(registro["ident"], registro["potencia"], registro["porta"])
de_csv        : ONU('onu-00042', -21.4, '1/1/1')
de_dict       : ONU('onu-00043', -29.8, '1/1/2')
na subclasse  : ONUXgs('onu-00044', -18.2)
tipo correto  : ONUXgs

A conversão mora num lugar só, o nome diz o que faz, e ONU.de_csv(linha) se lê melhor do que qualquer função solta. A biblioteca padrão usa esse padrão o tempo todo: dict.fromkeys, datetime.fromisoformat, int.from_bytes, Path.cwd.

A linha que mais importa é a terceira: ONUXgs.de_csv(...) devolveu um ONUXgs. É o cls fazendo o trabalho — ele é a classe pela qual o método foi chamado, não a classe onde foi escrito. Trocar cls(...) por ONU(...) quebra isso de forma silenciosa:

class Base:
    @classmethod
    def flexivel(cls):
        return cls()                   # respeita a subclasse

    @classmethod
    def rigida(cls):
        return Base()                  # ignora a subclasse
flexivel: Filha
rigida  : Base

Uma subclasse que chama Filha.rigida() recebe um Base — sem erro, sem aviso, e com o bug aparecendo bem longe dali. Dentro de um classmethod, use cls.

45.3 @classmethod: estado e política da classe

O segundo uso é operar sobre o que pertence à classe e não a uma instância:

class Coletor:
    _criados = 0

    def __init__(self, nome):
        self.nome = nome
        type(self)._registrar()

    @classmethod
    def _registrar(cls):
        Coletor._criados += 1

    @classmethod
    def quantos(cls):
        return cls._criados
criados: 3

Isto resolve o contador quebrado do Capítulo 41 sem repetir o nome da classe em cada método. Repare na assimetria deliberada: _registrar escreve em Coletor._criados explicitamente (para o contador ser global à hierarquia), enquanto quantos lê de cls._criados (para uma subclasse poder ter o próprio, se quiser). Escrever cls._criados += 1 criaria um contador separado por subclasse na primeira escrita — pela mesma assimetria entre leitura e escrita do Capítulo 41, agora um nível acima.

Uma variação comum é a instância única de configuração:

    @classmethod
    def carregar(cls, **valores):
        if cls._instancia is None:
            cls._instancia = cls(**valores)
        return cls._instancia
    criando pela primeira vez
mesma instancia: True
valores        : {'destino': 'olt-borda-01'}
    criando pela primeira vez
depois do limpar: {'destino': 'novo'}

Funciona, e vale a ressalva: estado global disfarçado de classe é difícil de testar e cria acoplamento invisível. O limpar() existe justamente porque, sem ele, um teste contamina o seguinte. Na maior parte dos casos, passar a configuração como parâmetro (Capítulo 44) é melhor do que buscá-la de uma classe.

45.4 @staticmethod: quando é mesmo útil

O método estático não recebe nem self nem cls. É uma função comum que mora dentro da classe:

class Potencia:
    @staticmethod
    def dbm_para_mw(dbm):
        return 10 ** (dbm / 10)
pela classe   : 0.007244
pela instancia: 0.007244
ida e volta   : -21.4000
via classmethod: 0.007244

O uso legítimo é estreito: uma função pura, fortemente ligada ao assunto da classe, que outros métodos da classe chamam. Como converter chama cls.dbm_para_mw(...), uma subclasse pode trocar a conversão sem que converter mude — o que uma função de módulo não permitiria.

Fora desse caso, o estático costuma ser um cheiro. A classe como saco de funções é o padrão mais comum:

class Util:
    @staticmethod
    def normalizar(ident):
        return ident.strip().lower()

    @staticmethod
    def validar(ident):
        return ident.startswith("onu-")
classe como namespace: onu-00042
funcao de modulo    : onu-00042

Mesmo resultado, e a segunda versão é melhor: Util não tem estado, não tem instância, não tem subclasse útil. Em Python o namespace é o módulo — from coleta import normalizar já é agrupamento suficiente. Uma classe usada só para prefixar nomes é hábito importado de linguagens onde não existe função de primeira classe.

O teste rápido: se um @staticmethod nunca é chamado por outro método da mesma classe, nem faz parte de uma interface que subclasses trocam, é uma função de módulo escrita no lugar errado.

45.5 __new__: antes do __init__

Existe um quarto tipo, implícito. __new__ é um staticmethod especial (o Python o converte automaticamente) que constrói o objeto, enquanto __init__ apenas o inicializa:

class Rastreada:
    def __new__(cls, *args, **kwargs):
        obj = super().__new__(cls)
        return obj

    def __init__(self, valor):
        self.valor = valor
    __new__  recebeu cls=Rastreada
    __init__ recebeu valor=42
valor: 42
    __new__ devolvendo outra coisa
resultado: 'nao sou uma instancia'

A segunda parte mostra a regra que pega desprevenido: se __new__ devolve algo que não é instância da classe, o __init__ não roda. É por isso que sobrescrever __new__ sem cuidado produz objetos meio-construídos.

O caso em que ele é obrigatório é o subtipo imutável, porque quando o __init__ roda já é tarde para definir o valor:

class Coordenada(tuple):
    def __new__(cls, lat, lon):
        return super().__new__(cls, (lat, lon))

    @property
    def lat(self):
        return self[0]
Coordenada(-23.55, -46.63)  lat: -23.55
TypeError: 'Coordenada' object does not support item assignment

Fora de subtipos de imutáveis e de alguns casos de cache de instâncias, __new__ raramente é a resposta certa — e, para o caso da coordenada, o NamedTuple do Capítulo 46 faz o mesmo em duas linhas.

45.6 Desenhando a API

Com as três formas na mão, dá para desenhar uma classe cuja superfície pública conta a história inteira:

class Leitura:
    FAIXA = (-40.0, 0.0)
    _total = 0

    def __init__(self, ident, potencia):
        self.ident = ident
        self.potencia = self._validar(potencia)
        Leitura._total += 1

    # --- construtores alternativos -------------------------------------
    @classmethod
    def de_csv(cls, linha):
        ident, pot = linha.strip().split(",")
        return cls(ident, pot)

    @classmethod
    def de_json(cls, texto):
        d = json.loads(texto)
        return cls(d["ident"], d["potencia"])

    @classmethod
    def lote_de_csv(cls, linhas):
        return [cls.de_csv(l) for l in linhas if l.strip()]

    # --- consulta sobre a classe ---------------------------------------
    @classmethod
    def total_criadas(cls):
        return cls._total

    # --- função pura, sem self nem cls ----------------------------------
    @staticmethod
    def dbm_para_mw(dbm):
        return 10 ** (dbm / 10)

    # --- interno --------------------------------------------------------
    @classmethod
    def _validar(cls, valor):
        valor = float(valor)
        menor, maior = cls.FAIXA
        if not menor <= valor <= maior:
            raise ValueError(f"{valor} fora de [{menor}, {maior}]")
        return valor


class LeituraXgs(Leitura):
    FAIXA = (-45.0, 0.0)
lote        : [Leitura('onu-00042', -21.4), Leitura('onu-00043', -29.8)]
de_json     : Leitura('onu-00044', -18.2)
subclasse   : LeituraXgs('onu-00045', -42.0)
tipo        : LeituraXgs
estatico    : 0.007244
total       : 5
ValueError  : -42.0 fora de [-40.0, 0.0]

Três decisões merecem destaque. _validar é classmethod porque lê cls.FAIXA — é o que permite LeituraXgs aceitar -42.0 enquanto Leitura recusa o mesmo valor, sem reescrever uma linha de validação. lote_de_csv chama cls.de_csv, e não Leitura.de_csv, então o lote de uma subclasse vem com o tipo certo. E __init__ continua sendo o construtor canônico e mínimo: todos os outros caminhos convergem para ele, o que garante que a validação nunca é contornada.

Uma última convenção, sobre nomes. de_csv, de_json e de_dict seguem o padrão de_<origem> da biblioteca padrão (from_bytes, fromisoformat). O par simétrico é o método de instância para_<destino> — para_json(), não Leitura.serializar(obj). Converter de algo é da classe; converter para algo é do objeto.

45.7 🐍 Jeito Pythônico

@classmethod para construtor alternativo, com o nome dizendo a origem. Um __init__ mínimo e canônico; todos os outros caminhos passam por ele.

# antipadrão: um __init__ que adivinha
class ONU:
    def __init__(self, origem):
        if isinstance(origem, str):
            ...          # é CSV? é JSON? é o ident?
        elif isinstance(origem, dict):
            ...
# pythônico: um caminho por origem
class ONU:
    def __init__(self, ident, potencia): ...
    @classmethod
    def de_csv(cls, linha): ...
    @classmethod
    def de_json(cls, texto): ...

Dentro de classmethod, use cls, nunca o nome da classe. É o que faz a subclasse funcionar; escrever o nome quebra em silêncio.

Cuidado com a assimetria em atributo de classe. cls.contador += 1 cria um contador por subclasse; Classe.contador += 1 mantém um só. Escolha de propósito.

@staticmethod só quando outro método da classe o chama ou quando ele faz parte da interface que subclasses trocam. Fora disso, é função de módulo — o módulo já é o namespace do Python.

__new__ só para subtipo imutável ou controle real de criação. Se ele devolver outra coisa, o __init__ não roda.

Nomes simétricos: de_<origem> como classmethod, para_<destino> como método de instância.

Agrupe a classe por seções — construtores, consultas, mutações, internos — e ponha os métodos internos com sublinhado por último. Quem lê a classe pela primeira vez lê de cima para baixo.

Sobre versões:

  • Python 2.2 — staticmethod e classmethod aparecem junto com as classes de novo estilo.
  • Python 3.0 — __new__ passa a ser convertido em staticmethod automaticamente.
  • Python 3.9 — classmethod passa a poder ser encadeado com property; o recurso é revertido no 3.11 por causa de comportamentos inconsistentes, então não conte com ele.
  • Python 3.10 — staticmethod e classmethod passam a ser chamáveis diretamente (Classe.__dict__["m"](...)) e a copiar __doc__ corretamente.
  • Python 3.11 — enum.property e enum.member resolvem o conflito entre property e membros de enumeração (Capítulo 46).

45.8 🧪 Laboratório

Objetivo: comparar os três tipos de método na prática, provar que cls respeita a subclasse e o nome literal não, ver __new__ rodando antes do __init__, e terminar com uma classe cuja API se explica sozinha.

1. O trabalho braçal.

mkdir -p ~/lab45 && cd ~/lab45

construtores.py: monte objetos a partir de CSV e de dicionário sem construtor alternativo, e conte quantas linhas de conversão o chamador precisa escrever.

2. Os construtores. Em classmethod.py, escreva de_csv e de_dict. Confirme o que mais importa:

na subclasse  : ONUXgs('onu-00044', -18.2)
tipo correto  : ONUXgs

3. cls contra o nome literal. Rode clsvshard.py:

flexivel: Filha
rigida  : Base

4. O estático. Em staticmethod.py, confirme que o método funciona chamado pela classe e pela instância, e que a ida e volta da conversão fecha em -21.4000.

5. Os três lado a lado. Rode tresformas.py. Confirme o TypeError do método de instância chamado pela classe e a tabela de tipos:

o que sai do dict da classe:
  instancia  -> function
  declasse   -> classmethod
  estatico   -> staticmethod

depois do acesso por ponto:
  declasse   -> method
  estatico   -> function

Explique por que estatico volta a ser function depois do ponto.

6. O contador. Rode contador.py e confirme criados: 3. Depois troque Coletor._criados += 1 por cls._criados += 1, crie instâncias de uma subclasse e veja os contadores se separarem.

7. A instância única. Rode singleton.py e confirme mesma instancia: True. Depois escreva dois “testes” em sequência sem chamar limpar() e veja o primeiro contaminar o segundo.

8. O saco de funções. Rode estaticoruim.py e reescreva Util como duas funções de módulo. Confirme que nada se perde.

9. __new__. Rode newinit.py e confirme a ordem das duas mensagens. Depois faça __new__ devolver uma string e confirme que o __init__ não roda.

10. O imutável. Rode imutavel.py e confirme:

Coordenada(-23.55, -46.63)  lat: -23.55
TypeError: 'Coordenada' object does not support item assignment

Tente escrever a mesma classe usando só __init__ e veja por que não dá.

11. A API completa. Escreva api.py e reproduza:

subclasse   : LeituraXgs('onu-00045', -42.0)
ValueError  : -42.0 fora de [-40.0, 0.0]

O mesmo valor aceito por uma classe e recusado pela outra, com uma única implementação de validação. Depois troque cls.FAIXA por Leitura.FAIXA dentro de _validar e veja LeituraXgs parar de funcionar.

12. O lote. Confirme que LeituraXgs.lote_de_csv([...]) devolve objetos LeituraXgs. Depois troque cls.de_csv por Leitura.de_csv dentro de lote_de_csv e veja o tipo mudar sem aviso.

45.9 Resumo

  • Método de instância recebe o objeto; @classmethod recebe a classe; @staticmethod não recebe nada e é uma função morando na classe.
  • No dicionário da classe eles são function, classmethod e staticmethod; depois do acesso por ponto, viram function, method (ligado à classe) e function de novo.
  • O uso que justifica @classmethod é o construtor alternativo: de_csv, de_json, de_dict — um __init__ canônico e um caminho nomeado por origem.
  • cls é a classe pela qual o método foi chamado. Usar cls(...) faz a subclasse receber o tipo certo; escrever o nome da classe quebra isso em silêncio.
  • classmethod que lê constante de cls (cls.FAIXA) permite à subclasse mudar a política sem reescrever o método.
  • A assimetria de leitura e escrita vale para atributo de classe: cls.x += 1 cria um por subclasse, Classe.x += 1 mantém um só.
  • @staticmethod se justifica quando outro método da classe o chama ou quando subclasses o trocam. Fora disso, é função de módulo — em Python o namespace é o módulo.
  • __new__ constrói, __init__ inicializa. Se __new__ devolver algo que não é instância da classe, o __init__ não roda.
  • __new__ é obrigatório para subtipo de imutável, porque no __init__ já é tarde para definir o valor.
  • Convenção de nomes: de_<origem> é da classe, para_<destino> é do objeto.

Escrever tudo isso à mão para uma classe que é só um punhado de campos é trabalho repetido: __init__, __repr__, __eq__, __hash__, os construtores. O próximo capítulo mostra as três ferramentas da biblioteca padrão que geram esse código por você.
